# 适老化 UI 审查——28-34fp 大字白话卡片流、高对比深色底、交互简化方案

## 一、审查范围与标准

本篇为 harmony-app（代号铃语）界面层的适老化审查知识资产。审查对象（均在本审查当日完整通读）：

- entry/src/main/ets/pages/Index.ets（459 行，主页面：卡片流 + 轮询驱动）
- entry/src/main/ets/pages/Settings.ets（558 行，设置页：NavDestination 子页）
- entry/src/main/ets/services/SettingsService.ets（456 行，字号档/适老化开关/主题色定义）

审查基准为项目不可逾越约束：适老化 = 28-34fp 大字白话卡片流，禁 K 线图等复杂图表；高对比深色底；首屏永不空白（服务未连通显示带「示例」字样演示卡）；交互简化（点卡即听）。对比度数值为本审查按 WCAG 2.x 相对亮度公式手工估算的近似值，非仪器实测，文中一律以"约"标注。

## 二、字号体系审查：主信息达标，辅助信息低于红线

Index.ets 以 fontLevel（'standard' | 'large'，SettingsService.ets:24）驱动七组字号 getter（Index.ets:51-71）：标题 titleSize 34/40、卡片题 cardTitleSize 30/34、白话结论 headlineSize 28/34、补充详情 detailSize 22/26、状态行 statusSize 20/24、播放钮 playBtnSize 28/32、角标 badgeSize 18/20（斜线前为标准档、后为特大档）。Settings.ets 另有 bodySize 28/34、labelSize 22/26、inputSize 24/28（Settings.ets:25-36）。

**达标面：** 标题、卡片题、白话结论（headline）三个核心信息位在标准档即 28-34fp，特大档 34-40fp，与红线一致；headline 是老人真正要读的那句话（契约里 headline 的定义就是"一句话白话结论"，model/AlertItem.ets:13），字号优先级给对了。

**偏离面（本篇最重要发现）：** 标准档下 detail 22fp、status 20fp、badge 18fp、label 22fp 均低于 28fp 红线。判定为**分级豁免的设计选择而非违宪**——detail/status/badge 属辅助信息（量能价位、刷新时刻、「自家信号」角标），主信息红线不被稀释的前提下给次级信息留出层级差，反而符合大字排版的可读性层级理论；且适老化模式开启时 setElderlyMode 强制 fontLevel='large'（SettingsService.ets:184-189），老人默认看到的 detail 是 26fp。但必须写明边界：若未来把 headline 也降到 28 以下，即是违宪，审查门槛（GOVERNANCE/skills/code/harmonyos-arkts-适老化开发.md 质量门槛"字体大小≥28fp"）应理解为"主信息≥28fp"并在此留档。

## 三、大字白话卡片流结构审查

卡片为 List + ForEach 结构（Index.ets:354-429），键函数取 item.alertId（:425），保证刷新时卡片按身份复用而不是按下标错位。单卡自上而下：未读金点（:361-365）→ 涨/跌/平色块字（dirLabel 单字 + dirColor 底色，:366-372、:289-307）→ 股票名（:373-380，单行省略）→「自家信号」描边角标（:381-389，仅 kind==='signal' 显示）→ 播放钮文案态「▶ 听 / ■ 停 / …」（:390-396）→ headline 大字（:400-403）→ detail 灰字（:405-410）→ 失败态「语音加载失败，点重试」（:412-417）。

审查意见：**信息结构正确**——一屏一问一句：这只股票涨了还是跌了（色块单字）→ 是哪只（名字）→ 发生了什么（headline 白话）→ 想知道更多（detail 可忽略）；红涨绿跌符合 A 股老人习惯且 dirLabel 用单字大色块而非百分比小数字，是正确的适老化抽象。空态文案「今日暂无异动 / 监测进行中，有新情况会自动推送」（:430-443）告知期望、不催促、不焦虑，符合"不输出催促性指令"红线。

## 四、高对比深色底审查

配色定义于 SettingsService.ets：夜间 NIGHT_COLORS（:41-49）页底 #0d1117、卡底 #1c2433、主字 #e8edf5、次字 #c6ceda、强调金 #f0b232、涨红 #e74c3c、跌绿 #2ecc71；白天 DAY_COLORS（:52-60）页底 #f5f7fa、卡底 #ffffff、主字 #1d2129、次字 #86909c。主题经 getThemeColors(mode)（:223-225）注入，autoTheme 默认开、6:00-18:00 白天否则夜间（:341-347），手动改主题会关掉自动（Settings.ets:103-110）。

按 WCAG 公式手算近似对比度（均相对卡底/页底）：

- 夜间主字 #e8edf5 对卡底约 13:1、对页底约 16:1——远超 AAA（7:1），深色底护眼省电与可读性兼得，硬约束达标。
- 夜间次字 #c6ceda 对卡底约 9.8:1、强调金 #f0b232 对卡底约 8.2:1——均 AAA 级。
- **问题一（中优先级）：** 涨跌徽标白字压色底——白字对涨红 #e74c3c 约 3.8:1（大号粗字 WCAG 大文本门槛 3:1，勉强过），白字对跌绿 #2ecc71 约 2.1:1（连大文本 3:1 都不到）。建议把 NIGHT fallGreen 压深（如 #1e9e57 一档）或徽标改深色字，二选一，改动点仅 dirColor 返回值与色表。
- **问题二（低优先级）：** 夜间「语音加载失败，点重试」riseRed #e74c3c 压卡底约 4.1:1，对 22-26fp 非加粗文本低于 4.5:1 的 AA 常规门槛，属边缘态文案，建议加粗或提亮红色一档。
- **问题三（低优先级）：** 白天模式次字 #86909c 对白卡约 3.2:1，对 labelSize 22fp 文本不达 AA；老人白天用机场景存在，建议白天 textSecondary 加深至 #6b7480 一档。

## 五、交互简化方案审查

1. **点卡即听：** 整卡 onClick 直接 togglePlay（Index.ets:423），无二级页、无长按、无滑出菜单；播放三态用文字词「▶ 听 / ■ 停 / …」而非纯图标（:390-396），老人不需要学习图标语义。这是全应用唯一的主动交互，符合"交互简化"上限。
2. **热区达标：** 设置入口文字按钮 constraintSize minWidth/minHeight 48（Index.ets:342-348）；设置页三处 Toggle 宽 60 高 48（Settings.ets:247-250、:279-282、:438-441）；免打扰时段 +/- 按钮固定 48×48（:293-301 等）；返回与删除项同样 ≥48（:157-167、:399-404）。48vp 起步的热区纪律全篇一致，值得保持。
3. **失败可自解释：** 语音失败在卡内就地显示「点重试」并把 failedId 记账（Index.ets:242-244、:412-417），点卡重走 togglePlay 即重试，不弹对话框、不跳设置——老人最怕弹窗，就地恢复是对的。
4. **布局呼吸感：** 适老化档下卡间距 20、卡内距 20、列表侧距 16（Index.ets:74-91 的 elderlyMode 分支），大字配大间隙，避免大字拥挤。
5. **导航极简：** 全应用两级——首页卡片流 + 设置页（Navigation + NavDestination，Index.ets:449-454；router.pushUrl 在 Stage 模型会产生 WARN 的坑已有技能文档留档，此处用 navStack.pushPath 是对的）。

## 六、首屏永不空白与状态可见性审查

三态兜底齐全：服务未连通时 DEMO_ITEMS 演示卡常驻（Index.ets:13-23），headline 自带「示例：」前缀、detail 写明「示例数据，服务器接通后自动换成真实异动」——既保证首屏有内容可看可点，又不把假数据冒充真行情，合规处理正确；连通但无异动时显示空态文案；连续失败 ≥2 次显示「连接中断，显示旧数据」（:195-199），保留旧数据而非清屏。顶栏常显刷新时刻（:332-334），系统状态对老人可见。

一处死代码：isDemoMode 状态声明并置 false（:34、:156），但 build() 中从未读取（本次 grep 全仓核实仅此两处），演示卡实际由 items 初始值承担。建议删除或实装为顶栏「演示中」徽标，二选一。

- P2 白天模式 textSecondary 加深（问题三）；失败提示红加粗（问题二）。
- P2 删除或启用 isDemoMode；同步清理 broadcastOffVisible 这类由 broadcastEnabled 派生的冗余状态（:38、:122，仅 loadSettings 赋值一次）。
