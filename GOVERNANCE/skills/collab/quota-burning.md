## 1. 额度资产分类

### 三种额度类型

| 类型 | 特征 | 管理策略 |
|------|------|---------|
| 限时窗口型 | 夜间免费、节假日促销、试用期 | 预排期，窗口内最大化消耗 |
| 持续配额型 | 月度免费额度、永久免费层 | 按需消耗，不急于燃烧 |
| 一次性券型 | 新用户券、活动券、补偿券 | 立即使用，防止过期 |

## 2. 燃烧策略设计

### 模型-任务匹配原则

| 模型特长 | 适配任务 | 燃烧效率 |
|---------|---------|---------|
| 中文代码生成 | ArkTS开发、云函数修复 | 高（持续可用） |
| 长文分析 | 文档熔铸、报告整合 | 中（限时窗口） |
| 深度推理 | 密码学分析、协议设计 | 中（消耗更多Token） |
| 语音合成 | TTS预生成 | 按量计费 |

### 时间窗口排期方法

```
燃烧排期表模板
├── 限时窗口型额度
│   ├── 窗口前：预排任务队列
│   ├── 窗口中：不间断循环产出
│   └── 窗口后：检查产出完整性
├── 持续配额型额度
│   └── 按需消耗，优先级驱动
└── 一次性券型额度
    └── 立即使用
```

### 燃烧效率最大化四原则

1. **长上下文优先消耗**：支持300K/1M上下文的模型优先派发需要长上下文的任务
2. **模型特长匹配**：不同模型擅长不同任务，匹配才能最大化产出价值
3. **串行依赖最小化**：可并行的任务分配到不同额度来源同时燃烧
4. **降级链保障**：每个任务都有降级方案——首选额度耗尽后切换到次选

## 3. 降级链设计

### 标准降级链模板

```
首选额度 → 次选额度 → 最终fallback
```

### 实例

```
密码学报告 → hy4-preview-f（首选）→ GLM-5.2（降级）→ Kimi（最终）
TTS生成 → DashScope（首选）→ 百炼WebSocket（降级）
代码审查 → GLM-5.2（首选）→ Hy4 preview（降级）
长文生成 → Hy4 preview（首选）→ GLM-5.2（降级）
```

### 切换触发条件

| 触发条件 | 动作 |
|---------|------|
| 首选额度余额不足 | 切换到次选 |
| 首选额度窗口过期 | 切换到次选 |
| 次选额度也不足 | 切换到最终fallback |
| 所有额度都不可用 | 标记BLOCKED，报告机主 |

## 4. 燃烧监控

### 监控指标

| 指标 | 目标 | 监控方式 |
|------|------|---------|
| Token消耗量 | ≥额度的80% | 平台用量统计 |
| 产出文档数 | ≥预定目标 | 文件系统检查 |
| 产出字数 | ≥预定目标 | 字数统计 |
| 窗口利用率 | ≥90% | 时间戳日志 |
| 质量评分 | ≥3分（满分5） | 自评+抽检 |

- 默认使用Flash（快速、低成本）
- C/D/F组标注[需深度推理]，切换到GLM-5.3
- Flash连续2个任务自评低于3分，自动切换到GLM-5.3
- GLM-5.3消耗速率过快，切换回Flash
- 窗口剩余<30分钟，强制Flash只做短任务
