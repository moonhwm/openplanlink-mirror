# 技能：24小时自治实验方法

> 所属：GOVERNANCE/skills/governance/ ｜ 版本：v1.0 ｜ 日期：2026-09-23 ｜ 适用项目：harmony-app（代号铃语，鸿蒙适老化股票异动播报应用）

## 一、定位与适用场景

24 小时自治实验是一次受控的"无人值守演练"：在约定时间窗内，工程按既定架构自动运行（数据拉取、卡片流渲染、TTS 播报、轮询兜底），治理流程自动运转（结果记录、CHANGELOG 追加、异常登记）；实验者只在起点与终点两个时刻介入，中途只观察、不操作。

它验证的对象不是某个单项功能，而是"工程 + 治理"整体在零人工干预下的自持能力。适用场景：

1. 治理体系首次搭建完成后的整体验收；
2. 重大变更后的稳定性验证（如数据源自 Tushare 降级东财 API、推送自占位封装切换华为 Push Kit REST）；
3. 席位交接前，向接手方证明系统可在低干预下自持；
4. 定期体检，建议每两周一次。

不适用场景：新外部依赖接入当天（应先做小时级冒烟）；已知合规红线未处置时（先处置再实验）。

## 二、实验设计

### 2.1 主假设与待答问题

主假设：零人工干预下，harmony-app 连续 24 小时满足"首屏永不空白、卡片流合规、播报链路可用"三条底线，且全部异常被记录体系捕获、复盘期可归因。

四个待答问题：工程侧（轮询、播报、首屏兜底是否稳定）；治理侧（记录是否完整可追溯）；缺陷侧（出现多少异常、多少被自动捕获）；修复侧（暴露的问题能否沉淀为技能或已知问题条目）。

### 2.2 指标体系

| 指标 | 口径 | 目标 | 红线 |
|---|---|---|---|
| 轮询可用率 | 前台 AlertPoller 每 5 秒对 FEED_URL 请求成功数 ÷ 总请求数 | ≥95%（交易时段） | <80% |
| 首屏非空白 | 冷启动到首卡（含带"示例"字样演示卡）渲染完成 | 100% | 出现 1 次空白即红线 |
| TTS 链路成功率 | audioUrl 为 undefined 时按需调 generate-tts 成功并播放完成的比例 | ≥90% | <70% |
| 卡片合规抽检 | 抽样文案不含承诺收益/保本、催促性指令、对外公开/收费表述 | 100% | 出现 1 条即红线 |
| 记录完整率 | 窗口内异常均有 CHANGELOG 或 incident 记录 | 100% | 缺 2 条以上 |
| 进程崩溃次数 | 应用异常退出次数 | 0 | ≥3 次中止 |

### 2.3 基线与对照

以实验前最近一个正常运转日为基线（从既有日志与 CHANGELOG 提取同口径数值），实验结果与基线对比，不与理想值对比。基线缺失时，准备期先补测 2 小时作为临时基线。

### 2.4 安全阀（中止条件）

出现任一情形立即中止实验并转入处置：应用崩溃连续 ≥3 次；卡片流出现任一合规红线表述；首屏空白 1 次；FEED_URL 连续 30 分钟不可达且演示卡兜底同时失效；任何 Token/密钥出现在日志或卡片文案中；日志断流超过 1 小时（治理体系无法记录的静默故障）。

安全阀被触发且留有完整记录，仍算实验有效产出；未留下记录就中断才是失败。

## 三、阶段划分

### 3.1 总览

| 阶段 | 时间 | 要点 |
|---|---|---|
| 准备期 | T-2h ~ T0 | 冻结、基线、清单 |
| 观察窗 A | T0 ~ T+6h | 覆盖开盘至午间 |
| 观察窗 B | T+6h ~ T+12h | 覆盖收盘前后 |
| 观察窗 C | T+12h ~ T+18h | 夜间无人时段 |
| 观察窗 D | T+18h ~ T+24h | 次日早段/非交易段 |
| 复盘期 | T+24h ~ T+26h | 汇总、评分、沉淀 |

四窗口设计目的：让实验至少跨一个完整 A 股交易时段与一个非交易时段，验证数据源、轮询、播报在"有数据"与"无数据"两种状态下都表现正常；窗口边界以整点对齐，便于日志切片与指标归窗。

### 3.2 准备期清单（T-2h ~ T0）

1. 冻结代码与配置：窗口内不部署任何变更，必须变更则实验顺延；
2. 状态快照：记录 FEED_URL 指向、东财 API 可用性、generate-tts 云函数版本、PushService 当前为占位降级轮询状态；
3. 三底线兜底确认：演示卡（带"示例"字样）可渲染、AlertPoller 兜底开启、音频播放失败有静默降级；
4. 建立实验目录 `GOVERNANCE/experiments/24h-YYYYMMDD/`，放入 metrics.csv、incident.md、report.md 三个骨架文件；
5. 追加一条 CHANGELOG 宣告条目（格式见 changelog-format.md，五要素齐全）。

### 3.3 观察窗纪律

每窗口结束时刻做一次 10 分钟内的"窗口小结"追加到 incident.md：本窗口异常数、是否触发安全阀、一句关键现象。窗口内发现异常只记录不修复（安全阀情形除外）。允许的操作仅限：查日志、截图、读 metrics.csv。

### 3.4 复盘期（T+24h ~ T+26h）

汇总 metrics.csv 算出各指标实际值；按第五章评分并出报告；追加 CHANGELOG 总结条目；把发现按 learning-loop.md 的闭环流程（结果记录→质量评估→模式识别→技能编写→复用）处理，技能文档格式遵循 skill-doc-format.md。

## 四、数据收集

### 4.1 采集点

| 采集点 | 数据 | 频率 |
|---|---|---|
| 端侧 hilog | 轮询请求/响应、渲染异常、播放错误 | 连续 |
| 云函数日志 | generate-tts 调用与耗时、数据源聚合结果 | 每次调用 |
| FEED 服务端 | AlertFeed 响应码与条数 | 每 5 分钟汇总 |
| 端侧截图 | 首屏与卡片流状态 | 每窗口 ≥3 张 |
| 人工观察 | 合规抽检、观感异常 | 每窗口 1 次 |

### 4.2 metrics.csv 格式

`timestamp,window,metric,value,note`，示例：

`2026-09-24T10:00:00+08:00,A,poll_success_rate,0.97,东财API正常`

一行一个指标一个窗口，window 字段取 A/B/C/D。

### 4.3 incident.md 条目格式

每条异常一段：`[时间] [级别] 现象 / 初步归因 / 是否触发安全阀 / 证据（日志行或截图路径）`。证据必须落盘；不接受无证据的"我看到了"式记录。

### 4.4 记录纪律

实时记录，事后补写不得超过一个窗口的内容；不记录、不粘贴任何 Token/密钥原文，涉密处写"凭据已脱敏"；原始日志按窗口归档（logs-windowA.txt 等），与 metrics.csv 同目录存放。

## 五、效果评估

### 5.1 单指标判定

每指标三档：绿（达标）、黄（未达标但高于红线）、红（触及红线或安全阀被触发）。

### 5.2 总体判定

通过：无红项且黄项 ≤2。有条件通过：红项恰 1 个且已归因、有明确修复方向，修复方向必须登记为已知问题或技能修订。失败：红项 ≥2，或出现"未被记录的异常"。

"未被记录的异常"单列为一票否决项：复盘时发现窗口内既无日志也无 incident 记录的异常，说明记录体系本身失效，比任何单点故障都严重。

### 5.3 报告与沉淀

report.md 固定五节：结论、指标表（目标/实际/档位）、异常清单（含归因）、修复方向、技能与文档修订建议。沉淀去向：新问题入 `GOVERNANCE/KNOWN-ISSUES.md`；可复用经验走 learning-loop.md 沉淀为技能。

## 六、与工程现状的对接

1. 轮询指标取自 Index.ets 卡片流页 5 秒前台轮询（AlertPoller）日志；
2. 数据源按现状统计东财 API：Tushare token 已失效（40101），实验不要求恢复 Tushare，只验证降级链路；
3. 推送链路为 PushService.ets 占位封装 + 降级轮询，只考核轮询兜底有效性，不考核推送到达率；
4. TTS 指标考核 alerts.json 中 audioUrl 为 undefined 时端侧按需调 generate-tts 的成功率（百炼 TTS 走 WebSocket）；
5. 首屏指标必须覆盖"服务未连通显示带示例字样演示卡"这一硬约束的兑现情况；
6. 架构基调（EntryAbility 的 Push 初始化与 onNewWant 带 alertId 拉起定位、AVPlayer 播云端 TTS 音频流、AlertFeed 契约）在实验期间视为不可变基线，实验只观察不改造。

## 七、常见失败模式

1. 把实验做成"值守"：窗口内忍不住动手改代码，实验作废，需重新约窗；
2. 指标不可采集：定义了落不了日志的指标等于没定义，准备期要逐一确认每个指标有采集点；
3. 只记工程不记治理：轮询日志齐全但异常未进 incident.md，复盘时治理侧无据可查；
4. 安全阀形同虚设：红线触发后"再看一会儿"，污染后续数据；
5. 复盘不沉淀：报告写完即结束，未走学习闭环，同类问题下个周期复发。

## 八、操作清单（速查）

1. 定窗口，发 CHANGELOG 宣告条目；
2. 准备期五项清单逐项打勾；
3. 四窗口：只读观察、窗口小结、metrics 追加；
4. 安全阀触发即中止并记录；
5. 复盘期出报告、追加 CHANGELOG、走学习闭环；
6. 归档实验目录，目录路径登记进 CHANGELOG 条目。

### 自我评估
- 正确性：4分 指标口径、阶段划分、安全阀与项目已知状态（东财降级、Push占位、audioUrl按需生成、演示卡兜底）一一对应，未杜撰事实；各项阈值为建议值，需首次实验后校准。
- 完整性：4分 覆盖实验设计、阶段划分、数据收集、效果评估四大要求，另补工程对接与失败模式；未含看板可视化与多日连续实验扩展。
- 可复用性：5分 表格、模板、清单、速查步骤齐备，无对话记忆依赖，任何席位可照做。
