# 部分失败容错

## 一、部分失败是多智能体的常态

单智能体系统只有全成或全败两种结局。扇出 N 路之后,出现第三种常态:部分成功。五路执行者三路成功、一路超时、一路输出不合格,此刻怎么办?把整体判败会浪费已获得的七成成果;无视瑕疵硬聚会污染输出。部分失败容错就是把这第三种状态从异常处理成一等公民,给出明确的取舍规则。

## 二、结果状态分级

处理部分失败的第一步是放弃二值状态,给每个子结果分级:

```text
done       完整完成,通过验收
partial    完成但带瑕疵(截断/低置信/缺字段)
timeout    超时,可能有中间产物可回收
invalid    完成但未通过验收
overload   下游过载,未真正执行
```

五级状态各自进入不同的处置通道:done 进聚合;partial 进聚合但带降权标记;timeout 先尝试回收中间产物再决定;invalid 与 overload 不进聚合,但进入重试或熔断判断。分级动作必须在执行者一返回就完成,不要拖到聚合期再猜测。

## 三、法定人数机制

聚合是否继续,由法定人数(quorum)决定。设定规则:

- quorum_ratio = 最小可用结果数 / 总派发数,按任务重要性分档,例如草稿类 0.5、正式类 0.8、关键类 1.0;
- 达到法定人数:聚合继续,缺席者以"缺失"标记进入输出限定语;
- 未达法定人数:不聚合,走降级路径(重试一轮、换源或直接告知用户能力受限)。

法定人数的深层价值是防止"幸存者偏差聚合":只有一路成功时强行聚出的结果看似完整实则片面,法定人数把这个质量风险转化成显式的失败,交由降级路径处理。

## 四、超时的中间产物回收

超时不等于零产出。执行者应周期性上报进度快照,超时被切断时,派发器拿到的最后快照往往仍有价值:

- 检索类任务:已取回的证据卡直接可用;
- 生成类任务:未完成草稿可作为 partial 素材;
- 分析类任务:已完成的子结论可用,未完成部分标记空洞。

回收纪律是"回收物必须如实标注不完整",任何对回收物的续写、补全动作都要留下痕迹,防止不完整产物被误当完整结论传播。

## 五、重试与放弃的决策表

部分失败后是否重试,按"价值 x 成本 x 可幂等"三要素决策:

```text
子任务价值高 + 可幂等 + 失败原因是瞬态  -> 自动重试(带上限)
子任务价值高 + 不可幂等                 -> 升级人工,禁止自动重放
子任务价值低 + 重试成本高               -> 放弃并标记缺失
失败原因是系统性(如源永久失效)         -> 换源而非原址重试
```

重试一律换新的幂等键变体或沿用原键配去重闸,禁止裸重放。系统性失败的重试是纯浪费,快速识别、快速换路是更优解。

## 六、聚合期的缺失表达

进入聚合的部分结果必须把"缺失"表达出来,而非静默忽略。推荐三种表达:输出的不确定性段落显式列出未覆盖的子问题;证据不支持的结论改用限定语陈述;关键维度缺失时整体降级为"部分回答"。用户或下游系统有权知道这是七成的答案,伪装成十成是部分失败治理里最恶劣的做法。

## 七、演练与验收

部分失败路径必须有混沌演练:人为让某一路超时、某一路返回格式错误、某一路过载,断言系统按预案降级而非崩溃。演练用例直接取自状态分级的五种状态各至少一个。没有演练过的容错代码,默认视为未完成。
