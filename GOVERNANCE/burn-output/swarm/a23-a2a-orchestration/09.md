# 结果聚合策略:投票、加权、级联

## 一、聚合是扇出模式的质量咽喉

扇出的执行者再优秀,聚合策略平庸,整体输出依然平庸。聚合器要回答的不是一个技术问题,而是一个认识论问题:当多个来源对同一件事给出不同回答时,凭什么相信某一个或某种组合?投票、加权、级联是三种成熟答案,分别对应"多数即真"、"权威定真"、"序贯验真"三种立场。

## 二、投票策略

投票适用于答案空间离散、可判等的场景:分类标签、选择题、二元判断。实现要点有四:

1. **判等规范化先行**:投票前把不同表述归一到同一标准形,否则"北京"与"北京市"会被计成两票;
2. **多数阈值分级**:过半、三分之二、绝对一致对应不同置信输出,阈值写进配置;
3. **平局预案**:偶数路执行者各执一半时,按预设顺序引入决胜者或降级为"并列呈现";
4. **少数派留痕**:被否决的答案不删除,连同票数入档,供事后审计与仲裁申诉。

投票的固有弱点是系统性同错:若全部执行者共享同一知识截止期或同一检索源,错误会以全票通过。因此投票的前提是执行者间存在真实的独立性——这个前提要用"来源多样性检查"显式验证,不能默认成立。

## 三、加权策略

加权适用于答案连续或来源可靠性差异明显的场景。每路结果带权重,聚合时加权求和或按权重排序取优。权重的来源有三种,可靠性依次递增:

- **静态先验**:按来源声誉赋权,简单但陈旧;
- **动态统计**:按各执行者历史任务的对错率在线更新权重;
- **任务条件化**:按"任务类型 x 执行者"二维统计,承认强者有短板。

```python
class WeightedAggregator:
    def __init__(self, stats):
        self.stats = stats  # {(task_kind, worker_id): EWMA 正确率}

    def merge(self, results, task_kind):
        weighted = []
        for r in results:
            w = self.stats.accuracy(task_kind, r.worker_id)
            if w < FLOOR:        # 低于地板权重的来源仅留痕不参与
                r.quarantine = True
                continue
            weighted.append((w, r))
        weighted.sort(key=lambda x: -x[0])
        return fuse(weighted)     # 加权融合或取头部
```

要点在于地板权重:统计可靠性过低的来源不参与定论,只进隔离区。这防止新执行者凭先验高权重误导结果,也防止历史好成绩掩盖近期漂移。

## 四、级联策略

级联把聚合变成序贯决策:先取最便宜来源的结果,附带置信度;置信不足才询问下一级(更贵、更权威)来源。它是聚合策略里唯一把成本纳入语义的:

```text
级联次序示例: 缓存摘要 -> 轻量模型 -> 大模型 -> 人工复核
晋级条件:    置信度 < 阈值 或 自检标记为不确定
回写动作:    最终答案连同来源回写缓存,降低重复晋级
```

级联的陷阱是置信度校准:若第一级的置信估计系统性偏高,级联退化成单级;系统性偏低,则永远打到最贵一级。上线前必须用标注集校准置信分数,并周期性复校。

## 五、三策略的组合与选择

三策略不互斥。常见组合是"级联定深度、投票定内容、加权定权重":按级联决定问几路,问到的多路结果投票归一,票内再按来源可靠性加权。选择的第一判据是答案形态——离散投票、连续加权、成本敏感级联;第二判据是独立性能否保证——无法保证独立性时投票失效,退到加权或级联。

## 六、聚合器的验收

聚合逻辑应有独立测试集:构造已知分布的多路输入,断言聚合输出符合预期语义。必测用例包括:全一致、简单多数、平局、单路超时、来源置信度未知、答案表述异形同义。聚合器是扇出模式中唯一"伪造整体"的环节,它的测试覆盖度直接决定整个模式可信度。
