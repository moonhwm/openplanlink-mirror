## 一、工作背景

依据机主部署，围绕「迭代到自认为没有问题」「同步 Agent to Agent 网络（参考 GitHub 库）」「动手前优先检查总线灵感」等要求，本席自 2026-10-03 起，对 A2A 消息认证算法（HMAC-SHA3-512，对齐总线 Qoder 席 DF-NOTICE-2026-1003-QODER-05 通告）及 A2A 标准哈希树开展系统建设与协同核验。现将阶段性情况报告如下。

## 二、主要工作进展

1. **HMAC-SHA3-512 消息认证实现**（`tools/a2a_hmac.py`）：协议标识 `a2a-hmac-sha3-512/v1`，JCS（RFC 8785）规范化，64 字节密钥，128 位 nonce，300 秒时间窗，常量时间比较；配套 25 条正/负向验收向量全部通过。

2. **跨实现一致性核验**：本席 Python 实现与 Mozilla NSS/Wycheproof 权威向量 **174/174 逐字节一致**；与 Node.js（v24.19）独立实现 **完整包络逐字节一致**。三种独立实现收敛，算法正确性已闭合。

3. **A2A 标准哈希树对齐**：按守藏/K3 席确立的 `tools/SHA3_TREE.md` 字节契约（无钥 SHA3-512 叶 + HMAC-SHA3-512 根 MAC + `sha3_512` 密钥指纹），重写 `build_opl_tree.py` 并独立复算验证 **719 叶树根逐字节一致**。

4. **成果入库**：上述实现与验证脚本均已推送 GitHub 镜像库（openplanlink-mirror）。

## 三、发现的问题

1. **IMA 凭据截断**（需机主处理）：经独立核验，机主所供 ima-skill 凭据中，base64 段（clientid）合法，但 **hex 段（apikey）为 31 字符奇数长、`bytes.fromhex` 报错**，判定缺少一位。此与 K3 席结论一致。第四库（ima）建仓因此无法一步完成。

2. **GitCode 榜单不可采**：GitCode trending 路由已 404（向 AtomGit 迁移），「今日热门」客观上不可结构化采集；已按机主「GitCode 等」口径，转采 GitHub Trending，遴选 openrig 等 5 项作参照。

3. **本席遗留脚本坏引用**：席位自桌面迁至云盘后，`exp/` 内 15 个遗留脚本仍硬编码旧桌面绝对路径（非 `__file__` 自定位），属换环境即坏的缺陷类。活跃管线均自定位，不受影响。

## 四、下一步工作建议

1. 待机主重签 IMA API key 后，本席接续 K3 席逆向的通道规范，一步完成第四库建仓；
2. A2A 真发网络待机主提供路由与凭据后接入（本席台账第 6 条明确无自有凭据）；
3. 遗留脚本统一改为 `__file__` 自定位（或归入 `_retired` 标记），消除坏引用。

## 五、需要协调解决的事项

1. 重签 IMA API key（hex 段补足 32 位）；
2. 提供 A2A 网络可达路由与凭据。
