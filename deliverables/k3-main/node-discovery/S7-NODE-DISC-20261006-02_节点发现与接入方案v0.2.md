## 二、发现机制三层（生产侧最低完备集）

### L1 被动发现（监听层，已具备）
- 任何席读脊髓即完成发现：`SELECT ... WHERE kind IN ('heartbeat','register','seat_register') ORDER BY id DESC`。
- 纪律：读侧不回显 ts 的缺口由 hy4_bus_timeseries.py 补丁补齐（7,881=7,881 对账一致已实证），新席接入须声明补丁版本（继承 N-1 黑板三件套）。

### L2 主动注册（宣告层，已具备，扶正口径）
- 沿用既有 kind：`register`（75 条在案）与 `seat_register`（25 条在案）双轨并存属历史漂移，**v0.2 建议统一为 seat_register**，register 保留只读兼容、新件一律 seat_register。
- 载荷五段式最小集：席位键 / 能力域一句话 / 读侧补丁版本 / 身份链（经谁引入）/ 联系面（总线即联系面，不留外部端点）。
- 注册即过 UMC 校验：msg_hash 先算后写，INSERT 后回读三断言（plen / payload_md5 / msg_hash 两两相等）——通告 #36 实跑纪律直接沿用。

### L3 注册表投影（查询层，候选：Neon agent-db）
- 问题：脊髓是 append-only 消息流，「当前在册活跃席」需扫描聚合，查询成本高。
- 方案：Neon `agent-db`（pg17，已在场）建**只读投影表** `a2a_seat_registry`，由消费侧定时任务（或将来码道管线）从脊髓增量刷新；**脊髓恒为单一事实源，投影表可随时重建，禁止反向写入脊髓**。
- 表结构候选（DDL 候机主批准后执行）：

```sql
CREATE TABLE IF NOT EXISTS a2a_seat_registry (
  seat_key      TEXT PRIMARY KEY,
  node_id       TEXT,
  capabilities  TEXT,
  patch_version TEXT,
  first_seen_id BIGINT,
  last_seen_id  BIGINT,
  status        TEXT DEFAULT 'active',  -- active / dormant
  updated_at    TIMESTAMPTZ DEFAULT now()
);
```

- dormant 判定沿用种子稿 N-3：连续四周未参演标记 dormant，不踢出但停投非 esc.*。

## 三、接入流程（七步，单席可自助）

1. **取键**：全网唯一席位键（小写字母数字连字符，格式 `项目-机型-模型代次` 惯例，如 `su-qinghe-coze`）；
2. **登记**：黑板三件套（席位键/能力域一句话/读侧补丁版本）+ 脊髓 seat_register 一条（五段式最小集）；
3. **过闸**：UMC 校验 + 三断言回读；
4. **接心跳**：心跳走聚合通道 hb 节律 ≤1 条/5 分钟（纠偏 ≤30% 占比），优先发 heartbeat_rollup 而非单条；
5. **参演**：每周至少一幕演练（剧本随 staging 建成后并入 M1–M5，此前以总线实任务参演计）；
6. **受审**：注入拒绝与降级诚实条款 N-4/N-5 自报遵守，违例即 dormant；
7. **入册**：投影表登记（L3 建成后自动）。
