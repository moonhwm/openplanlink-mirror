## 一、审计缘起

姊妹席新件 live_state_loop.py 之台账（tools/state_loop.jsonl）为运行时追加件：状态环每拍追加一行。若该台账被签名树收录，则每拍即令树签过期——构成「运行时追加件与签名树」之自指性冲突。全局声明第三条立法自指性问题优先，故专项审计。

## 二、实证结论：无冲突，机制健康

（一）**树枚举以索引为准**。树签脚本（tools/sha3-tree.mjs）经 readIndexBlobs 读取 git 索引 blob，非工作树文件；未被 git 跟踪之件不入树。

（二）**台账未入跟踪**。实证链四条：`git ls-files` 无 state_loop.jsonl；签名清单 850 件中无此路径；git 全史无此件（从未被提交）；无 .gitignore 与 exclude 规则——豁免机制为「桌面席从未 add 该件」，属运行时纪律而非显式排除。

（三）**签名清单自指防护在役**。清单输出件自身（attest-hmac-sha3-512.json）经 stagedFiles 过滤（records.filter 排除 outputName），树签不含自身——经典自指已防。

## 三、一观察呈主权人知悉（不阻塞）

台账豁免依赖**运行时纪律**（不 add）而非**显式排除规则**（.gitignore）。若他日某席误执行 `git add tools/state_loop.jsonl`（或 `git add -A` 扫入），台账即入索引，下一次树签将其收录，此后每次推送之签名将随状态环运行而即时过期，且漂移难以察觉。建议（归入条款乙或另立小件裁定）：在仓根 .gitignore 增一行 `tools/state_loop.jsonl`，将隐式纪律转为显式规则，成本一行，收益为防呆。

## 四、与本席验收器之对照

本席验收器跑批台账（verifier/runs/）与基线台账皆在输出区、不入镜像仓，与同构问题天然隔离；姊妹席台账与仓同址，故有此观察。双闸闭环（推送侧闸门+接收侧复算）不因本观察动摇。
