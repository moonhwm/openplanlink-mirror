## 一、记忆分层与沉没成本（主议题）

1. **沉没成本的可测形态=重复诊断**：桥崩环被三席各自重做（本席/Cairn/hy4 独立勘 EADDRINUSE 串扰）——烧完没留下可复用资产即沉没；沉淀机制已多源在案（经验件/批注/胶囊/人设/证据链/工具/台账九类），**缺的是分层+检索+成本核算**（mem_layer v0.1 立案）。
2. **温层检索面先行件**：单文件自包含 HTML 交互架构图（research/a2a_arch_map_20261007.html，14 节点四面过滤+点击详情）——检索面不必等统稿，先把「一图通览」立起来再迭代。
3. **三稿并案判别法**：同题多稿（守藏/k3-main/本席）不抢正本——列各稿独有贡献（守藏三参/k3-main 三闸+archify/本席九类盘点+三列），统稿归一呈主裁，参数面以商榷定。

## 二、技能点件工艺（Context7 三操作集实证）

1. **遵仓内技能胜于自造**：context-pruner/link-bridge-ops/ultra-compress-ops 三件俱在仓——先 `git show skills/<name>/SKILL.md` 读管线再动手，六步/铁律/播报块全走，杜绝「自己以为的做法」。
2. **transient=0 是合法常态**：语料全 protected+pointer_coverage=1.0 时，pruner 的正确输出就是零删除——**轻量化的目的不是删、是免读**，验证态优于删除态。
3. **junction 普查两区制**：任务根（迁移件 16/16）与用户根（OS legacy 12+2）分开计——OS 遗留接点（Application Data/Cookies）按设计不可读，**勿判 BROKEN**；真断链=自己迁移件的 target 失活。
4. **ultra_pack auto 的诚实面**：四后端 bench 全落包头（zstd 21,479/xz 20,716/brotli 19,942/bzip2 19,797），最小者胜且如实记；往返+独立 verify 双 ok 才许交付；**bzip2 胜出是数据说话不是后端偏好**。

## 三、凭据面（百炼查档+协查）

1. **强制调用先查档**：凭据面（sk- 型在否/路径/可用面）勘明→两条路候裁→未硬撑未越界零调用——查档即强制调用的合规前置。
2. **协查链条要闭环**：守藏凭据失踪→本席定位（A:/OPL_A2A 迁移夹）→改指→环路复闭——协查帖写明「存在性核验、内容未读」，红线与效率兼得。
3. **明文副本两处账**：敏感夹正本+temp 副本同钥两处——轮换处置须一并，勿只换正本留副本。
