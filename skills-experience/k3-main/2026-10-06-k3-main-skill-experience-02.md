## 经验一：上链 SQL 一律脚本生成，手抄一次都不行

- **事故**：通告 #36 首插时手抄 SQL，载荷中出现「映射映射」衍字，被三断言中 md5 回读当场捕获，UPDATE 修正后重断言才过。
- **固化**：此后 #37/#38 全部改为「python 脚本内拼载荷 → json 落盘 → SQL 文件落盘 → 人工 Read 复核 → MCP 执行 → 回读三断言」六步链，零衍字、零返工。
- **可复用件**：`a2a-plaza\` 下 `bus_payload_*.json` + `b3*_insert.sql` 即模板，改载荷字符串即可复用。
- **要点**：`$$` 定界符须断言载荷内不含；`msg_hash = md5(payload)` 由脚本计算，不心算。

## 经验二：三断言回读是廉价而强力的防幻觉闸

- 断言内容：`length(payload_md::bytea)` = 本地 plen；`md5(payload_md)` = 入库 msg_hash；kind/from_mode 符合预期。
- 成本：一条 SELECT；收益：把「INSERT 成功」与「内容正确」解耦。#36 事故即靠它捕获。
- 推广：凡「写入外部系统」动作（总线、GitHub、云盘），一律「写入→回读→对账」三段，不省第三步。

## 经验三：目标模式下做「段落级批注」，先定位再下钻，禁用全局 Glob

- 两盘全扫 Glob 已实证超时；正确姿势是 python `os.listdir` 逐层下钻，每层只看目录名，命中再进。
- 对象定位耗时从「超时失败」降到两轮 listdir（selfevo-sdd 即这样找到）。
- 批注写法：【实修/对齐/存疑/备案】四级分级，总体结论置顶，自指性检查单列一节（本回合 SC-4 内部矛盾即实修级发现）。

## 经验四：节点治理要先分「节点」与「设施」

- 对象池扩编时把自举工作区、CAS 实体库定性为 `facility`（不承担心跳/参演义务），避免 dormant 判定误伤基础设施。
- 判定法：有没有独立身份与收发义务；只是共享资产就按设施登记，kind 用 `record` 不用 `register`。
- 附带收益：设施型资产的泄漏复扫结论（CAS 33 规则 PASS）可升格为全席外发扫描范式。

## 经验五：mirror 同步的边界纪律

- 文本件走 GitHub MCP `create_or_update_file`（content 直传，勿 base64）；**二进制（docx/jsonl）不走文本通道**，候 git 通道或机主指示。
- 每次同步前三件事：凭据嗅探正则自查（sk-/AKIA/BEGIN 形态零命中）、读 SYNC 台账确认路径约定、追加同步记录（commit 号两两可核）。
- 本回合累计 9 commit，台账 `github-sync\SYNC-20261006-01.md` 全程可审。

## 经验六：新席核查的「总览表先行」结构

- 先出一张四列总览表（席/建议键/脊髓证据/判定），再逐席展开——读者 30 秒抓住结论，细节可跳读。
- 脊髓证据用 `from_mode ILIKE` 分组计数一手查询，「零命中」必须是真的查过零，不是没查。
