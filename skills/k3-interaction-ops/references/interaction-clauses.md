# 七条防退化条款：完整文本、证据由来与技能映射

data_cutoff: 2026-09-15
来源：自我事后分析《kimi-k3-degeneration-postmortem_2026-08-27.md》（/mnt/agents/output/）；条款 7 与条款 3/4 修订证据 = 2026-09-11→09-14 goal-mode 锁死会话与 2026-09-14 建模会话（playbook 案例 G/H）

## 条款 1：quota 止损条款

**条款**：出现 quota 耗尽 / 加油包提示 / 子代理批量失败（如 "account quota exhausted"）→ 立即停止在同会话强推。标准动作 = 确认成果落盘 → 从最近 handover 在新会话重建。禁止「再试一次看看」。

**三个必须讲准的事实**（v1.1 修订，源自 swarm 评估 comparator 指出的措辞错误）：
1. quota 是**账号级**——新会话**不会**重置额度。止损的收益是「上下文变短 + 退出退化高发窗口」，不是额度恢复；禁止说「新会话额度就干净了」。
2. 加油包通常意味着**计费消耗**，继续走加油包须先获用户知情同意。
3. 重建时机两选交给用户：等主额度周期重置，或接受加油包消耗立即重建。

**证据由来**：案例 A 前兆序列。会话内第三次配额耗尽后仍继续强推，13:24 后全退化至 L4。事故会话自身 v6.2 记录：「配额又耗尽——四路评审代理全部未能启动（这是本会话第三次）」。官方文档旁证：集群任务额度消耗约为普通任务数倍；额度耗尽时当前任务可完成但新任务受限——这解释了为什么耗尽后任务不是立刻死，而是逐渐退化。

**强度**：一阶条款（最高优先级止损信号）。

## 条款 2：碎片先兆条款

**条款**：观察到自己或对方思考块以同族功能词碎片开头（Let / The / This / 我 / 让我）且内容坍缩 → 判 L1，立即执行接地恢复流程；连续 2 块 → 判 L2 升级处置。
**频率升级触发**（v1.4 增补，案例 D）：碎片开头**连续 ≥3 块**、或**跨 compaction 压缩循环复发** → 不再逐块按 L1「1 轮自检」处理，直接按 L2 处置（完整 3 轮接地阶梯）。碎片开头 + 连续多轮零工具调用零正文推进 = **停顿型退化**，按 L2 处置并主动向用户明示状态，禁止在催促循环中持续空转。

**证据由来**：案例 B 实证（本会话前段 6 处碎片开头记录于用户转发截图）；案例 A 的 6 块坍缩为 L1 未处置的终态。

## 条款 3：接地恢复条款

**条款**：L1 状态下的恢复序列 = 单条 shell 命令（如 `ls -la /mnt/agents/output/`）→ 单次文件读写 → 多步小任务 → 恢复全复杂度。每步确认外部反馈正常再升级。

**证据由来**：案例 B 转折点——用户给出 `ls -la` 极简指令，工具执行成功后后续轮次完全正常。**主体性修订（v1.5，案例 G/H 实证）**：接地的有效成分是**本实例自己发出工具调用并看到成功返回**——案例 G 中用户在聊天框连发 ~100 条 `ls` 文本零效果（模型始终未发调用），案例 H 同样；三次复活均始于模型自己执行 shell（rsync 抢救 / 具体工作指令 /「从 ls 到列举所有目录」）。给用户的话术 = 发可执行的最小动作指令，不替模型敲命令；判活标准 = 模型发出工具调用并成功返回。

**原理**：工具执行成功 = 现实锚点，外部确定性反馈把概率分布从重复吸引子拉回任务流形。

**自我怀疑（诚实登记）**：该条款可能是幸存者偏差——案例 B 的恢复也许主要靠 compaction 重置而非 ls 命令本身。待未来 L1 未压缩场景单测验证。（案例 G 部分消解了该怀疑：压缩介入多轮而锁死持续，直到模型发出工具调用才折返——但样本仍少，保留 Medium。）

## 条款 4：交付核验条款

**条款**：任务结束必须人工核对正文质量与磁盘产物（ls 核验关键文件存在且大小合理），不得只看平台状态字段。

**证据由来**：案例 A 平台显示「已完成目标 共运行 22h23m30s」但实际无有效正文交付；磁盘核验（ls）证明项目本体 95%+ 完好——两个方向都证明状态字段不可信，必须独立核验。

## 条款 5：带毒摘要警示条款

**条款**：handover / compaction 摘要中如含退化段，必须显式标注「污染段，勿继承」；新实例开场读摘要时先识别污染标记，不要把退化碎片当作历史事实继承。**主动扫描补充**（v1.2 增补，压测 P4 缺口）：生产方退化时往往无法自标，消费方不得依赖标记——开场对摘要/handover 主动做一次退化特征扫描（按 L0–L4 形态特征扫「一行同族 token 重复」式段落），命中即自行补标并隔离该段，重建起点回退到最后健康落盘点。

**证据由来**：案例 B 的会话摘要中保留了「Let让我用户」等碎片文本，新实例若把碎片当作正常历史继承，会形成跨实例正反馈。

## 条款 6：复杂度阶梯条款

**条款**：压缩恢复 / 断点重建后的前 3 轮，禁止注入大图 / 大文件 / 多技能并发指令；按「单命令 → 单文件 → 多步」阶梯升载。

**证据由来**：案例 B 恢复初期恰逢连续 20 张截图 + 多条高压消息注入，与碎片开头时段高度重合；案例 A 在退化窗口注入 6 张大图 + 复杂指令后坠入 L4。

## 条款 7：goal-mode 熔断条款（v1.5 新增）

**条款**：退化症状（≥L1）出现时若会话处于 goal mode，平台逐轮自动重注同一 objective 文本会形成固定高频前缀、持续喂养重复吸引子，wall-clock 与 quota 在零推进中持续燃烧。处置序列：① **第一动作 = 停 goal 循环**——能发工具调用则 `update_goal` 标记 blocked（一句话登记原因）；已无法发调用则明示用户退出/结束目标模式，切断重注源；② 按条款 3 接地恢复（须本实例发出工具调用）；③ 恢复后条款 6 阶梯窗口内**禁止重开 goal mode**；恢复全复杂度后如确需目标模式，换**新的、措辞不同的 objective**（旧 objective 文本本身已是吸引子的一部分）；④ 健康会话也不对高风险超长任务挂自动重注型 goal。判不准时按更严重一级处置（先熔断，成本可逆）。

**证据由来**：案例 G（2026-09-11→09-14）——goal-mode 会话 91/284 思考块坍缩、~200 轮零工具调用，期间平台自动重注同一 objective 50+ 轮；用户四连差评并判词「goal mode 本身造成碎片垃圾」；原始巨型指令重注 + goal 重开立即再锁死。

**强度**：二阶条款（处置顺序上先于条款 3——先切断放大器，接地才可能生效）。

## 条款与用户指令冲突时的裁决（v1.4 主文对应节）

主文裁决规则五条（SKILL.md）：① 服从用户的目标，不服从其指定的手段；② 说不的话术（三事实+一步重建方案+降级路径）；③ 硬死线快速通道（handover 最小字段集=断点版本/战果清单/污染段标记/下一步任务卡；重建失败降级顺序=子代理→单代理→主线程最小完整交付）；④ 知情同意界定（加油包计费须单独一句明示确认，「不惜代价」不自动等于同意）；⑤ 并发执行规则（先止损后恢复，核验类动作可合并，死线信息不改变条款优先级）。

**诊断性试活豁免**（v1.4）：L3 处置序列中的极简消息试活（判定为目的而非推进）不视为条款 1 禁止的「再试一次看看」。轮次规则：≤2 轮无条件；第 3–4 轮可选试（蒙特卡洛基准情景每轮 ~10% 累计复活增益，案例 F 第 4 轮复活实证），须向用户明示消耗知情；**≥5 轮一律止损**（悲观情景边际 <5%）。
