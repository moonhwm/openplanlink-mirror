# 金融分析专著交付闸门管线（monograph-delivery-ops）

定位：与 monograph-forge-ops 互补不重叠——那件管「怎么写」，本件管「交付前怎么验死」。本件从「稿已成形」接管，到「机主批准交付」为止；写作期闸门一律回 forge-ops。

## 一、主流程（八步，序号即依赖，跳步=返工）

1. **开工门·六原型选型**：输入=读者画像与书稿定位；输出=选定原型+一句话选型理由。先答「读者拿它干什么」再谈一切下游：学术型=引用你的数字；咨询 deck 型=拿去开会说服人；调查型=理解一个群体；研报型=查具体数据；论文型=同行评审；科普型=无背景读者理解一个领域并据此行动。**选错原型是最贵的错误**——原型选错，下游每道自检都在为错误的交付形态抛光。爸爸专著默认科普型骨架+研报型的多页免责声明组件。
2. **🔴 选型门（候批）**：输入=第 1 步选型结论；输出=机主批准记录。把选型与理由呈机主，**停在原地候批**。候批语义：此门未批，后续步骤一律不动；「用户说继续」不替代对具体选型结论的确认。
3. **数据承重层立法**：输入=底稿表；输出=数据表.json+verified 位责任人名单。数据表.json 是承重口径：每个数字的 basis 必须写成一句完整话，写不出完整话的数字不进正文；verified 位权责开工时立法——仅亲自读到一手来源的核验责任人有权置 true，调研席永不置位。
4. **图表生成**：输入=数据表.json+图型选择；输出=内联 SVG 图件。用 chart.py 八函数（第二节）；文字空间一律由 text_w 反算，不许写死；含负值数据必须走 paired_bars 零线逻辑。
5. **渲染与页码收敛**：输入=build.py+base.css+输出路径；输出=PDF 与收敛轮次记录。**渲染前先把 build.py 留副本**——render.py 的 patch_toc 会改写 build.py 源文件，这是它唯一的写操作。目录页码只许 locate/patch_toc 循环回填收敛（至多 4 轮），不许手写。
6. **🔴 渲染前门（候批）**：输入=收敛记录；输出=机主批准记录。呈机主确认三样：build.py 副本已留、收敛在 4 轮内完成、base.css 承重段零改动。任一项答不出→候批不通过，停线补齐再呈。
7. **自检四层+四闸对接**：输入=PDF/HTML/xlsx/docx 交付物；输出=各层各闸退出码与报告。顺序不可颠倒：文本层机械自检→几何自检→长文档三项（章≥6 才跑）→四闸→EYE_ONLY 人眼层。任一闸退出码 1→停线修复，修完从断点重过全链。
8. **🔴 交付总闸（候批）**：输入=全部闸门退出码 0+人眼清单销号记录；输出=批准交付或退回。免责锚在位、合规四件过闸、清单逐条销号后方可呈批。总闸未批=未交付；「先发了再说」即交付事故。

## 二、图表层：chart.py 八函数用法与适用场景

| 函数 | 适用场景 | 关键纪律 |
|---|---|---|
| hbar | 类别名较长的横条比较 | 标签区与数值区由 text_w 反算，不写死 |
| stacked_row | 构成占比（行和=100） | 段宽>26 才在段内标百分比 |
| paired_bars | 成对柱、含正负变化 | 负柱从零线向下画，ymin<0 必加零线 |
| line_chart | 时间序列折线 | 末端直接标注系列名，不用图例 |
| big_stat | 大数字视觉锚 | 一页最多一个，画布按 text_w 反算防折断 |
| diverging | 李克特量表发散条 | 负左正右，中线即零点 |
| slope | 「从 A 到 B」排名/水平变化 | 两端直接标注名称与数值 |
| quadrant | 双维象限散点 | 50 处虚线十字，个体直接标注 |

- **text_w 反算纪律**：一切标签留白由 text_w 估算、clamp_x 夹回画布；写死宽度必在中文长标签上折断或出界。
- **负值零线坑**：「下降 11% 画成零高度」是金融图高发事故；凡数据含负值，图型选择与纵轴范围先过零线检查再生成。

## 三、渲染层：三文件架构与 base.css 契约

- **三文件解耦**：数据表.json（承重口径+verified 责任人制）/ build.py（正文+CSS+组装 HTML，项目方自写）/ render.py（渲染器+自检器）。
- **页码收敛链**：render.py 每轮无条件重建 HTML→playwright 渲 A4 PDF→pdftotext 逐页定位各章起始页（跳过目录页）→patch_toc 把页码回填进 build.py 的 toc_row（toc_row 必须写在一行内）→页码不再变化即收敛。
- **base.css 契约**：调味段（设计令牌变量）按视觉方向换值；承重段（分页容器页眉跨页重绘、表格防粘连四件套、长 URL 防缩版、孤儿段防护、图表整块不劈）**不许改**——每一条都带实测事故记录，手写基座复现这些坑的概率极高。

## 四、自检层：四层顺序不可颠倒

1. **文本层机械自检**：编号混用与重复、目录页码存在性、内容极少页、tuple 痕迹、占位符形状。假警报比漏报更贵，不许调宽阈值换全绿。
2. **几何自检**：pdftoppm 把每页渲成灰度图，逐页实测四边留白毫米数，低于阈值报页码；全出血页自动跳过；另列「下半页大面积留白」候选页。**CSS 写了不算，实测才算**。
3. **长文档三项**：章数≥6 才跑——单章加粗超预算、章长方差超 2 倍、中文标点后残留空格；只报数不自动修，改哪句由人定。
4. **EYE_ONLY 人眼层**：九类机械查不出的缺陷（列缝粘连、图表被切、居中标注边缘被切等）；章首场景、比喻承重等判不了的项只进人眼清单；300 页以上用「12 页拼一张检查表」两档分辨率扫法。抽检对排版缺陷无效——缺陷集中在最复杂的页。

## 五、四闸对接（沙箱实测口径）

| 闸门 | 职责 | 实测坑 |
|---|---|---|
| verify_numbers | 合计行交叉对账+--claim 外部核对 | 无标题行两列窄表被吞表头→假阳性；先加宽列或人工核表头识别 |
| verify_xlsx | 行高装不下、列宽不足、合并吃数据、冻结空行 | 宽度类检查只在显式设过列宽时执行；边界情形降 WARN |
| verify_docx | 中文 run 缺 eastAsia 即 FAIL、图片超版心 | 缺字体时渲染项跳过并明示「不等于通过」 |
| verify_visual | 画出 viewBox、标签重叠、横向溢出、图数不一致 | 库已装但浏览器二进制缺失时 traceback+退出码 1，与内容失败同码 |

- **合计行=免费校验和**：不许删，它是原作者用公式算过的真值。
- **退出码三态必须可区分**：0=过 / 1=有 FAIL / 2=环境缺依赖未验；「没验」与「验过」混同即闸门失效；跳过项印「跳过≠通过」。

## 六、规则分层判据：「能写成函数的规则不许留在手册」

- **已函数化（必须落脚本层）**：编号混用、占位符残留、tuple 痕迹、页码回填收敛、逐页留白实测、负值零线、文字空间反算。
- **半函数化**：加粗预算、章长方差、标点后空格——机器报数，人定改哪句。
- **只能留清单（人眼层）**：章首有没有具体的人和时刻、比喻能否承重、basis 是不是一句完整话、原型选型——机器判不了，硬编成函数=假闸门。
- **验证口径（仓颉 v2.5）**：来源充分性、可执行性、任务增益三重验证；判据四路分流 verified/reference/needs_review/rejected，缺口记 needs_review 不静默消失；用户确认不能替代来源验证。

## 七、失败模式编码（如果失败→则）

1. 如果 verify_visual 退出码 1→先分辨环境失败还是内容失败：跑自带自检或查堆栈；确认是「库已装、浏览器二进制缺失」→用 shim（把浏览器路径指到系统 Chromium）或补装二进制后重跑，不许把环境故障记成交付物不合格。
2. 如果 verify_numbers 对干净表报 FAIL→先查是否无标题行窄表被吞表头：加宽列或补真实标题行后重跑，仍 FAIL 再人工核表头识别结果，不许直接改数硬凑。
3. 如果渲染后 build.py 被 patch_toc 改写→拿渲染前副本比对：差异仅限 toc_row 页码则确认收敛，否则回滚副本并停线查原因。
4. 如果章首场景、比喻承重类检查项机器判不了→只登记进 EYE_ONLY 人眼清单逐条销号，不许硬编函数冒充已检。
5. 如果几何自检报留白不足→改 build.py 版式后重渲重测，不许以「CSS 已写 padding」结案。
6. 如果页码 4 轮不收敛→停线查 toc_row 是否写在一行内、章首锚正则是否误中目录页，不许手写页码收尾。
7. 如果章数<6→长文档三项不启用，但须在自检报告明写「未跑」，不许省略记录。
8. 如果任一闸门缺依赖→退出码 2+未验清单随交付物存档候批，不许当通过。

## 八、反模式黑名单（不要做）

1. 不要把仓方自报数字（42 份、98%、2.8%、+161% 之类）当已验证事实引用——「+161%」在仓内全文零命中。
2. 不要跳过 🔴 门说「用户说继续」——候批是对具体结论的确认，不是对「继续」二字的确认。
3. 不要手写页码——页码只许 locate/patch_toc 循环回填收敛产出。
4. 不要改 base.css 承重段——调味段可换，承重段每条都带事故记录。
5. 不要把「会调用」当「做得对」——判据只有退出码与报告内容。
6. 不要把合计行当冗余删了「清爽数据」——那是白送的校验和。
7. 不要把环境缺依赖的退出码 2 当通过，也不许把 verify_visual 的环境 traceback 当内容失败。
8. 不要用抽检代替逐页人眼层，不要为「全绿好看」调宽任何阈值。
