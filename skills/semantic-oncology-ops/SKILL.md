# 语义肿瘤防治运维（semantic-oncology-ops）

> **能力自报块**（总接口 I3）：能力域=管理+通道｜输入型=会话状态/长文档/交接请求｜输出型=防治方案+交割卡+通道消息｜只读性=否（写通道表/台账，须用户授权域内）｜依赖=Supabase MCP（通道）、python3 标准库
> **纪律继承声明**（I4）：本技能继承 conf 词表统一、红线条款、写类例外、信息充分性条款、全局共同遵守（autonomous-advance-ops 为准）。k3-interaction-ops 的 L0–L4 光谱与六条款为本件 §1–§3 的病理学底座（引用不复制）。

## 定义（学术锚定，conf=estimated+）

- **语义污染（semantic pollution）**：会话/文档生态中，失真内容被当作事实继承并扩散的状态——含退化碎片、虚假声称、跨文件混植、摘要失真四类本体（学术对应：semantic drift=输出渐进偏离原始任务意图 [Agent drift, Rath 2026]）。
- **上下文压缩病（context compression）**：超长会话触发自动压缩，摘要有损致版本号/计数/状态/路径漂移（survey: methods/failure modes/evaluation, 2026；选择性压缩的摘要保真度，Li et al. 2023）。

## §1 压缩避免审计（最小代价防线）

按代价从低到高排序的防线，能用前一级不用后一级：
1. **输出预算**：每轮工具输出上限自律（大返回截断采样、CSV 不落全文进上下文）；
2. **最小作用量**：核验只读板+胶囊+锚点，不重读全档案（既有立法，本件强制化为第 1 道）；
3. **大输入切分**：长文档/图集按分块审核条例（10% 重叠带+整体复核）；
4. **主动小结**：预估逼近压缩阈值时，主程序主动产出中间交接件（不等被动压缩）；
5. **档位提醒**：预判大体量任务首轮即提醒用户确认长对话档位（既有立法）。

## §2 退化救活规程（K3 集群恢复大使）

**适应症**：会话已严重退化（L2–L3）但需其写出基本/必要交割文档。
**救活阶梯**（先试活轮次规则：≤2 轮无条件，3–4 轮可选须明示消耗，≥5 轮止损——k3 条款）：
1. **模式切换试活**：K3 集群→K3 单线程/普通长度切换（**实证先例登记：K3 集群长对话切换 K3 普通长度曾救活医学专业文档**——用户提供的案例，登记为救活路径甲）；
2. **极简消息试活**：单命令→单文件→多步阶梯升载（接地恢复）；
3. **最小交割卡**：救活目标降级为「能写出一张交割卡」——模板五字段：断点版本/战果清单（落盘指针）/污染段标记/下一步任务卡/风险声明。写不出全文时按此卡即算救活成功，禁止要求完整交接文档；**落盘指针纪律（v1.1.0）**：指针必须落 /mnt/agents 持久位；引用 /tmp 件视同无效指针——/tmp 不跨会话保留，涉 /tmp 中间件必须附「从持久位母件重建」的步骤说明；
4. **误伤防护**：救活动作不改动该会话既有落盘（只读核验+追加写）；**K3 极致模式优势登记**：集群并行/长上下文宽裕仍是复杂任务首选档位——救活≠贬低 K3 集群，模式切换是病例适配不是档次判决；
5. **不治处置**：≥5 轮试活仍坍缩 → 止损（不再注入指令），抢救落盘，从最近健康 handover 重建。
6. **提示模板吞没型退化（v1.1.0 新增，实证病例：K3 集群 R+6，2026-09-11）**：
   - **识别信号**：用户拉回指令（「清理碎片」「锚定自我」类）发出后**零工具调用、零落盘**，思考链呈同族 token 碎片刷屏（LetLetLet/TheTheThe 型），正文零有效交付——判「指令被提示模板吞没」，不判「用户指令无效」。
   - **根因登记**：compaction 后 goal-mode/verifier 平台提示模板与长任务上下文叠加，触发 token 级退化循环。**平台机制对抗禁忌**：goal-mode/verifier 属平台机制（机主判「官方的坑」在案）——注入更多同型拉回指令=喂循环，绕开不硬碰。
   - **接地规程**：改发**接地型短指令**=要求一个具体文件系统动作（ls 核验现场/读单个文件），**以文件系统为准重建状态**，恢复工具调用后再阶梯升载；**禁止在退化思考链上空转续写**。
   - **冷启动建议**：接地交割完成后，精细迭代（长链推理级）不再交原会话，建议新会话从交割文档冷启动接续。

## §3 语义污染肿瘤学（癌症分期防治）

| 分期 | 名称 | 处置 |
|---|---|---|
| 预防期（一级预防） | 未污染防护 | handover 卫生（交接前落盘核验）、引用不复制、双轨纪律（姊妹会话内容本体不互传）、登记式表述（禁完成式指针指未落盘件） |
| 早期（筛查） | 定期筛查 | 消费方开场退化特征扫描（一行同族 token 重复式段落）；锚定回放+逃逸回放每轮；冗余扫描器定期跑（§5） |
| 中期（遏制） | 污染局限化 | 命中即标注「污染段，勿继承」并隔离；污染时间窗内触写文件逐一内容核验；禁止并入交付与摘要 |
| 晚期（治疗） | 病灶切除 | 污染段物理剔除留墓碑标记；回退只作用叙事层不作用磁盘状态；坏文件单独修复而非整体回退 |
| 转移防控 | 跨会话扩散 | 带毒摘要警示（生产方退化时往往无法自标，消费方不得依赖标记）；交接函件含污染声明字段 |
| 复发监测 | 跨压缩循环 | 碎片开头跨压缩循环复发→升 L2 处置（既有立法）；每轮自审计首查复发信号 |

## §4 Supabase 跨模式交流通道（kimi chat ↔ kimi work K2.6/K3/K3集群）

- **表**：`cross_mode_channel`（id/ts/from_mode/to_mode/kind/payload_md/status/msg_hash，RLS 启用，2026-08-30 用户授权落成）。
- **写纪律**：用户授权范围=通道消息写读；其余 Supabase 写类仍逐次批准（授权不扩散）。通道消息禁含密钥/隐私/未脱敏家庭信息。
- **协议**：发件=insert（from_mode/kind/payload 五段式回执文本/msg_hash=md5(payload)[:16]）；收件=轮询 status='new' → 读 → 标 'read' 或 'accepted'/'rejected'（交割语义沿用 consignment-intake-ops 状态机）；交接文档 kind='handover' 时 payload 须含最小交割卡五字段（§2.3）。
- **能力边界声明（v1.1.0 新增）**：本节依赖 Supabase MCP。在无可达 Supabase MCP 的端（实证：K2.6 端连用都用不到——机主 2026-09-11 实证在案），本节按**能力占位**显式声明「通道不可用」，禁止假装可用、禁止空转重试凑轮；退化到「交割文档落持久位+下一会话冷启动读取」的文件接力通道（不依赖任何 MCP）。
- **五道审查（授权时已过）**：范围=通道消息（封闭✓）/时限=至用户撤销（明确✓）/撤销=一句话（存在✓）/逃逸面=RLS+内容闸（✓）/红线=不冲突（✓）。

## §5 冗余自审计与定期运维

1. **冗余扫描器**：`scripts/redundancy_scan.py`——条款级复写检测（写类例外/红线/I9/信息充分性/授权法典/引用不复制六类），输出复写级嫌疑清单；处置原则=母本留全文、其余改一句指针（规范 I8）。
2. **定期运维节奏**：每周（或每 10 轮迭代取先到）跑一次扫描+INDEX 核对+台账健康检查（额度/交割/计时器三台账字段完整性）；结果入迭代日志（零发现如实报零）。
3. **自审计首查项**：本技能自身条款与其他技能的重复（创刊即声明：§1/§2 为既有立法操作化引用，不复制原文）。

## top3_likely_wrong
1. 「医学文档救活」先例为用户口述单案例（conf=Medium，无文档佐证），救活路径甲的普适性未证
2. 癌症分期为隐喻框架（启发式非医学类推论），分期边界判错风险存在——误判按更重一期处置
3. Supabase 通道轮询无实时性（非 webhook），跨模式交接存在延迟窗；且通道在部分端（K2.6 实证）整体不可达，文件接力为唯一保底——保底通道延迟窗更大
