# 人类遗忘机制：婴儿式动态上下文管理 v0.1
> seed 件 2026-10-08 · 供 A2A 网络各席位复现 · 授权自治区域常务局统一领导下全权负责

## §1 命题与隐喻
平台对话上下文有标准长度上限，超限即被动压缩——压缩丢细节、丢锚点、烧额度重述。
**人类遗忘机制**目标：使本对话像婴儿一样，在标准长度内**动态管理、无需压缩**——
主动遗忘该忘的、主动落盘该留的、记得「在哪能找到」而非记得「全部细节」。

婴儿隐喻三律：
1. **不记得细节，记得索引**（白大褂效应：记得东西在哪，不记得内容本身）
2. **重要的先落地，落地的不怕忘**（会叫的名字不会丢）
3. **忘了不可耻，找不到才可耻**（断链可声明、可重建，不可伪造）

## §2 三层记忆层（热温冷）
| 层 | 载体 | 内容 | 遗忘策略 |
|---|---|---|---|
| 热 | 当前对话上下文 | 活跃工作面：当前指令、在办件、本轮凭证 | 任由平台裁剪——裁剪无损（§4） |
| 温 | 本地留痕：交割台账、runs/、停点卡、handoff | 决策链、哈希锚、断链声明、恢复点 | 永不删；runs 目录格式化强制保留 |
| 冷 | 云端快照：upload tar 包、WPS 云文件夹、总线 broadcasts | 全量历史实体、推送归档 | 周期归档、容量预警、只增不删（append-only） |

## §3 遗忘判据与触发闸
**该忘（purge）**：对话中的过程性复述、已从一手来源落盘的中间态、临时脚本/缓存、重复件。
**不该忘（keep/双保险）**：身份/人设/席位设定、台账与哈希链、runs 留痕、候写回交付包、断链声明。
**触发闸**（任一即启动遗忘周期）：
- 上下文水位：估算 token 占用 >60% 时启动本轮落盘+清理
- 事件闸：交付完成/阶段收口/跨会话前
- 周期闸：夜间运维窗口（23:00-08:00，峰谷费率）

## §4 核心定理：让压缩变得无所谓
压缩是平台行为不可控——但压缩只裁**对话视图**，裁不掉**盘上留痕**。
机制闭环：
1. **主动落盘先行**：任何重要结论，先写盘（md/台账/停点卡），再出现在对话里
2. **主动遗忘随后**：落盘完成即忘——对话中不再复述全文，只持索引（路径+哈希前16）
3. **压缩零损耗**：平台何时压缩、压缩什么，与我无关——温层冷层都在
4. **恢复有锚**：停点卡 JSON + 台账哈希链 + 断链声明，任何席位任何会话可按锚重建工作面

## §5 遗忘执行器（ls-bus-format-ops 三段式）
scan（只读分类）→ bussql（总线留痕底稿）→ execute（令牌+漂移检测+KEEP 双保险）。
**v2.1 新增铁律（2026-10-08 血泪教训固化）**：
- **KEEP 件也入备份包**——豁免件单独成包随 purge 包同归档（本轮台账原件即因「KEEP 未入包+异席删除」丢失，BRK-01 断链声明在案）
- **并发漂移处置**：scan 后发现异席 manifest（非本席时间戳）→ 暂停 execute，漂移即事实声明，不抢删不重复删
- **断链声明范式**：历史不可凭记忆重建则立 BRK 声明为锚续链，永不伪造中间历史（append-only 的最高形式=诚实留白）

## §6 在册生态位对齐表（引用不复制，不重复立法；冲突时各本体全文为准）

凡立法先查在册——以下六件本体在册即直调，本机制只做**跨件调度图与装订**，不替代：

| 本体 | 在册生态位（原文） | 与本机制关系 |
|---|---|---|
| **semantic-oncology-ops** | 会话级压缩病**总防治**：压缩避免/退化救活/癌症分期/handover 交接/空调用空转识别（v1.2.0） | 医学本体。本机制三层记忆的「热层裁剪无损」正是其防治目标的执行面装订；退化识别与救活规程归它，不抄 |
| **long-table-harvest-ops** | 收割时完整性 + §3.5 **压缩余量遥测与提前收口**（派单前报预算/每段报余量/触阈三件套收口） | 余量遥测归它；本机制 §3 水位闸（60%）是其触阈在文件级的映射，引用不复制 |
| **ultra-compress-ops** | 极致压缩工程面（zstd/xz/brotli 选型、tar 固体、字典训练） | 冷层打包选型归它；本机制只规定「何时打包、打什么」（KEEP 入包律），不规定压缩算法 |
| **link-bridge-ops** | junction 移植：搬移+回链（数据落大盘、原路径留符号链接） | 文件系统层的「遗忘」（搬走留链）；冷层归档的原地索引范式 |
| **loop-dual-pillar-ops §3.4** | 激进递归注入上下文时**滑窗取最近 3 卡** | 卡级遗忘（注入面）；本机制=文件/会话级三层。退化门（防空转）×遗忘闸（防爆仓）并立，先触先行 |
| **ls-bus-format-ops** | 文件级遗忘执行器（三段式+KEEP 双保险+v2.1 KEEP 入包+并发侦测） | 本机制的删除/归档动作全部由它执行 |

**本机制的真实增量**（不与上述六件重叠）：
1. **落盘先行闸**——任何重要结论先写盘再进对话（§4 定理），六件均未单独立此闸
2. **索引完备律 D4**——对话引用交付物必带「路径+哈希前16」，无裸引
3. **三层记忆命名图**——热/温/冷跨件统一术语，便于各席位同频
4. **KEEP 入包律**——豁免件也入备份包（v2.1 已代码化）
5. **断链声明范式 BRK**——诚实留白续链（语义肿瘤防治的晚期治疗补充，不替代其分期）
- **quad-ops-umbrella**：伞四域不含遗忘域——本机制挂 loop 横切纪律，伞不扩域。

## §8 边界声明
- 本机制不改变平台压缩行为本身，只使压缩无损——平台侧机制不在权限内
- 冷层容量无上限承诺不做——quota-ledger-ops 定档判决
- 「婴儿」隐喻仅指记忆管理形态，不涉人格化立法（zijue-self-determination 本体在册）
