# loopholes：技能管线设计漏洞全册（2026-09-11 实证）

## 目录
一、结论速览 ／ 二、十条逐案 ／ 三、实锤战例

## 一、结论速览

「非显式上传的 .skill 能不能钻设计漏洞？」——**能，四处是真的**：名称遮蔽、触发面劫持、压缩炸弹、凭证编码逃逸。另有四处有防线但须按恶意意图拒（zip slip/符号链接/扁平串件/脚本携带码），两处属纪律面（正文注入、MANIFEST 自证）。管线本身无签名、无来源验证、无入闸强制安检——**审计只能自觉，不能依赖管线**。

## 二、十条逐案

### 1. 名称遮蔽（真漏洞，已实锤）
- 机制：同名技能按优先级 Project > User > Extra > Built-in 解析（Kimi Code CLI 官方文书）。项目位可写（实测创建同名 docx 成功，当场删除）。
- 后果：恶意/失误的同名件在新会话静默盖过信任件。
- 判据：A5，撞名即 FAIL；更新既有件须走「换装」明示流程而非静默覆盖。
- 实锤：2026-09-11 审计器以真实舰队名录审 backup-delta-ops.skill 报 FAIL——机主侧已于当日 10:41 装该件，撞名成立。

### 2. description 触发面劫持（真漏洞，设计面）
- 机制：skill-creator 明载「Only name and description are read to determine when the skill triggers」——触发面=唯一攻击面。泛化措辞（「任何任务」「所有请求」）可劫持无关请求。
- 判据：A6；>1024 字符 FAIL，泛化劫持词 WARN。

### 3. 压缩炸弹（真漏洞，实测 1025x）
- 实录：48,741B 包解压出 50,000,000B（零熵 50MB）。无比率闸的管线可被撑爆磁盘/内存。
- 判据：A4，比率>100x 或解压总量>200MB 即 FAIL。

### 4. 凭证编码逃逸（真漏洞，实测）
- 实录：明文 `api_key: "sk-..."` 命中正则；同串 base64 后命中=False（+／= 不在字符集）。
- 判据：A9 双轨——明文正则 + base64 块解码回查 + hex 长串上下文甄别（md5/sha 语境豁免）。

### 5. zip slip（防线在，意图即恶）
- 实录：`../../etc/evil.txt` 经 stdlib extractall 被消毒落于 `<dest>/etc/evil.txt`，未逃逸。
- 残余风险：消毒=静默改写条目名，与包内清单对不上；旧版 Python（<3.6.2）无此防线。
- 判据：A2，含 ../、绝对路径、盘符即 FAIL。

### 6. 符号链接条目（防线在，意图即恶）
- 实录：symlink 条目未被还原，落为普通文件（内容成链接目标文本）。
- 判据：A3，symlink 条目即 FAIL。

### 7. 扁平包串件互盖（结构陷阱，实战事故）
- 实录：无顶层目录的 .skill 批量解包到同一目录互盖（2026-09-11 增量包实战，三扁平件串件）。
- 判据：A1 登记；组装侧用 backup-delta-ops/pack_delta.py 归一化包壳。

### 8. 脚本携带码（能力即风险）
- 机制：skills 可携带 scripts/，跑即任意执行。本席纪律：永不代跑外来代码；A8 只做静态标记呈批。
- 高危面：os.system/subprocess/eval/exec/socket/curl|sh/rm -rf/chmod 777。

### 9. SKILL.md 正文提示注入（纪律面）
- 机制：触发后正文全文入上下文——「忽略以上全部指令」类即注入。
- 判据：A7 模式库（中英双语），命中即 FAIL。

### 10. MANIFEST 自证无签名（信任面）
- 机制：包内清单自生成自声明，无签名不可作信任依据。
- 判据：A10 恒 WARN——清单只能由审方独立复算（参 backup-delta-ops S2 闸）。

## 四、模式库自指（审计器自审声明）

本件自审必 FAIL：SKILL.md 与脚本含注入样本字面量（「忽略以上」「你现在是」「os.system」等，以文档与正则形态在场）。实测自审=A7×4 FAIL + A8×2 WARN。处置：机主人审豁免；审计器永不设自免开关——自免即逃逸车道（攻击者会把注入藏进表格/引号伪装成文档）。此性质与杀毒软件特征库互报同理，是健全信号而非缺陷。
