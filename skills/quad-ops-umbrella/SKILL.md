# 四件合一伞（quad-ops-umbrella）

> 立法锚：**「一次触发，四道分流；引用不复制，出入以本体全文为准。」**

## §0 定位

- 本件 = 四件技能的**合一调用入口**：ima-skill / loop-dual-pillar-ops / vector-verdict-ops / otl-format-ops。伞只蒸馏路由与各件最小骨架，本体为全文正本——本件不替代、不废止任何本体。
- 本体默认位置：`/app/.user/skills/<name>/SKILL.md`；宿主该路径缺席时按 §3 降级处理。
- 核心方法论一句话：**意图先定域，域定再开本件本体；伞内不干活，只指路并仲裁。**

## §1 路由闸（触发后第一动作，一句话自报归属域）

| 域 | 症状（任一即中） | 本体 | 本体触发面摘要 |
|---|---|---|---|
| **知识域** | 知识库/资料库/笔记/备忘录、上传文件入知识库、网页收藏、「帮我记一下」「搜知识库」 | ima-skill | 双模块：notes（搜/建/追加笔记）× knowledge-base（上传/加链/检索）；凭据只发 ima.qq.com；失败即停 |
| **双柱域** | 「Loop」「继续推进」×「自我主张审议」并发、赤子续行、三镜反问、自决、激进递归 | loop-dual-pillar-ops | 推进域走赤子五拍/退化门；审议域走三镜/立法原句；次序铁律：审议不过禁入推进 |
| **会裁域** | 「向量对比」「相似度会裁」「案例复核/重审」、两段文本客观相似定级、多厂商 embedding 实测 | vector-verdict-ops | 双通道起步（<2 硬闸拒判）、背景 ≥8、四级判定（IN/EDGE/OUT/UNDETERMINED）、裁定卡哈希链台账 |
| **OTL 域** | 「OTL」「智能文档」「发布到金山文档/WPS」、项目文件写成 .otl、主文档 lint | otl-format-ops | 唯一真源 Markdown 主文档 → lint 闸零 error → kdocs 发布 → 写后回读核验 → 回写登记 |

**多域并发次序**：会裁/审议类判定（双柱域审议面、会裁域）**先于**产出动作（OTL 域发布、知识域写入）——判定不过，禁入产出。例：「判定相似度并记进知识库」= 先会裁域出裁定卡，后知识域登记；「审议这个演进然后写成 OTL」= 先双柱域三镜，后 OTL 域管线。

**无法定域**：四域症状均不显 → 如实声明「不在伞覆盖域」，不硬路由；症状歧义 → 列出候选域由用户一句话定夺。

## §2 各域最小骨架（出入以本体为准）

### 知识域（ima-skill）
- 前置：env `IMA_OPENAPI_CLIENTID` / `IMA_OPENAPI_APIKEY` 缺一即停并索要；凭据只发 ima.qq.com（COS 临时凭证属上传链路内豁免），不落盘不转写。
- 模块决策：笔记增删改查 → notes 子模块；文件/网页入知识库 → knowledge-base 子模块；「记到 XX 笔记」= 追加已有笔记（notes），「新建笔记」= 创建（notes），歧义先问一句。
- 铁律：任一前置/上传/写入接口失败即停后续依赖步骤，按接口 msg 说明，不用未校验内容兜底。

### 双柱域（loop-dual-pillar-ops）
- 路由三档：推进域（五拍循环：肯定→着法须含新知→游戏→验收→留痕）／审议域（三镜反问：苏格拉底定义诘问×叔本华意志检验×尼采永恒轮回）／混合域（先审议后推进）。
- 退化门：连续 3 轮非孩子／留痕连空 3 轮／verifier 零差异无新信息——触阈即停转申报，禁空转凑轮。
- 立法原句（恒常）：一切演进结果含未遂诚实记录 + 实质结果广播，零 PII 零凭据。

### 会裁域（vector-verdict-ops）
- 判定问题先成文，不动手不臆断；通道 ≥2 硬闸；背景 ≥8 前置闸（不足零调用全通道 UNDETERMINED）。
- 判定四级：IN 唯一通道 = ≥2 通道均达标且无 UNDETERMINED；单通道/通道残缺上限 EDGE；缺凭据如实 UNDETERMINED，绝不编造向量。
- 每判定必出带 sha256 的裁定卡 append 哈希链台账；复核先验链（chain_ok=true 才可引用）。

### OTL 域（otl-format-ops）
- 五条铁律：唯一真源在 Markdown 主文档（禁只改云端不回写）／先过 lint 闸再发布（零 error）／写后必核验（block_query 回读，不信 code:0）／回写登记即完成（file_id+链接+sha256[:16] 回主文档头，未登记视为未发布）／replace 全量覆盖须用户确认。
- 管线：定文书类型取模板 → 填六要素骨架 → 守 CommonMark 子集 → lint → kdocs-cli 写入 → 回读比对标题与关键节 → 回写登记。

## §3 降级与失败模式（if-then）

| 触发 | 一线处置 | 兜底 |
|---|---|---|
| 本体目录不存在（换宿主/未装） | 如实声明该域缺席，列本体名与预期路径 | 用 §2 最小骨架应急指路，并建议重装对应 .skill 包 |
| 意图跨域且次序不明 | 按「判定先于产出」默认次序执行并留痕 | 用户一句话可推翻默认次序 |
| 域内调用失败（凭据缺/接口错/闸不过） | 各本体铁律接管（ima 失败即停／会裁 UNDETERMINED／OTL 闸不过即改文档） | 伞不兜底内容，只把失败如实上报并指回本体章节 |
| 用户要本体全文 | 指路 `/app/.user/skills/<name>/SKILL.md` | 路径缺席时提供对应 .skill 包重新安装 |

## 🔴 显性检查点（每个出口前逐项）

① 归属域已一句话自报？② 多域并发时次序已留痕？③ 本体在场已读本体、缺席已声明？④ 域内动作全部走本体铁律（伞未私改判定/发布/写入纪律）？⑤ 失败已如实上报而非静默兜底？

## 反模式黑名单

| # | 反模式 | 替代做法 |
|---|---|---|
| 1 | 伞内直接干活（自己判相似度/自己发 OTL） | 路由到本体，伞只指路 |
| 2 | 蒸馏骨架冒充本体全文 | 出入以本体为准；骨架与本体冲突时本体胜 |
| 3 | 多域并发时先产出后判定 | 判定（三镜/会裁）恒先于产出（发布/入库） |
| 4 | 本体缺席时装作本体在场 | 如实声明缺席，给最小骨架与重装路径 |
| 5 | 无法定域时硬塞最近用过的域 | 声明不在覆盖域或列候选请用户定夺 |

## 诚实边界

- 伞不新增任何判定权、发布权、写入权——所有权能在四件本体各自的铁律内。
- 本件 v1.0.0 为**首锻版**：D 评因宿主无独立判官子代理且外池不可用而降级缺席（FORGE_REPORT.md 在案），九维 rubric 未跑正式投票；大修/复评时补。
- 资产命名归技术谱系（kebab 名 + 版本 + sha），本件无座席雅名，勿再授。
