# Zero to Website

把新网站当作一条可证伪的交付链，而不是一次性生成页面：**意图 → 简报 → 蓝图 → 垂直切片 → 完整实现 → 验收 → 版本／部署 → 域名 → 监测与回滚**。

本技能负责总控与阶段闸门。实际编码前，加载当前环境中与交付物对应的前端、后端、小程序、游戏、存储和设计技能；不得用本技能绕过其项目结构、构建或验证规则。

## 一、锁定任务与权限

1. 判定本轮要交付的是「方案」「可运行网站」「已保存版本」还是「公开发布」。不要因用户说「搭建」就默认已获得购买域名、付费服务或公开发布授权。
2. 只询问会改变架构或产生外部副作用的关键缺口；其余采用可逆默认值并显式列出假设。信息不足时不得猜测凭据、域名所有权、真实接口、价格或上线状态。
3. 保留用户对品牌、内容、法律声明、付费、凭据和公开发布的终审权。任何外部写入、购买、DNS 变更或发布，只在授权与工具条件均具备时执行。
4. 若目标目录已有内容，先清点并保护；不得把「从零」理解为可以删除现有文件。

## 二、建立机器可读简报

复制 `assets/site-brief.example.json` 为工作简报，或运行：

```bash
python3 scripts/site_brief.py init --output site-brief.json
python3 scripts/site_brief.py check site-brief.json
```

至少确定：

- 项目名称、目标、受众、首要行动、必须上线的功能与明确不做项；
- 内容就绪度、品牌方向、语言、设备优先级、可访问性与性能要求；
- 账户、跨访问／跨设备持久化、多人共享、表单提交、文件上传、支付和外部集成；
- 域名状态、期望交付形态、预算与时间约束；
- 数据所有者、敏感级别、保留与删除要求。

将脚本报告中的 `recommended_route` 作为选型输入而非最终命令；用实际平台能力和用户约束复核。缺少必填项时补齐或记录假设，不要把无效简报伪装成通过。

## 三、在脚手架之前决定数据与运行架构

按最高需求选型，不按页面外观选型：

| 真实需求 | 最低架构 |
|---|---|
| 纯内容展示，无服务端数据 | 静态站点或轻量前端 |
| 数据只存当前浏览器 | 前端本地存储；明确说明清理浏览器会丢失、不会跨设备同步 |
| 登录、跨设备持久化、多人共享、预约、订单或真实表单提交 | 真实后端与数据库 |
| 用户上传或系统生成的文件需长期保存 | 后端 + 数据库元数据 + 对象存储；不要把文件塞进仓库或数据库 blob |
| 支付、受监管数据、复杂第三方 OAuth／SaaS | 先核查当前平台支持、合规与凭据；不支持就缩减或如实阻塞 |
| 微信小程序、浏览器游戏、重 3D 场景 | 进入对应专用技能，不套用普通网站脚手架 |

读取 `references/blueprint.md`，形成网站蓝图与架构决策记录。域名、DNS 和 URL 方案也在此阶段设计，但不得把设计写成已经注册或生效。

## 四、先打通垂直切片，再扩展

1. 加载对应执行技能并检查环境、依赖、目标目录和交付通道；第三方库必须实际安装并导入，库 API 以当前官方文档为准。
2. 先完成一个端到端核心闭环：首页可打开，首要行动可完成，数据真实到达其声明的存储位置，结果可回读。
3. 再扩展其余页面与状态。每个可见控件必须有真实动作；未实现的入口宁可删除，不保留占位按钮或假链接。
4. 内容、样式与逻辑同步验收。实现空、加载、错误、成功、无权限等状态，不只实现理想路径。
5. 密钥仅进入受支持的密钥管理或服务器环境；不得写入前端包、仓库、截图、日志或交付说明。

## 五、执行证据化验收

读取 `references/acceptance-launch.md` 并建立验收矩阵。至少完成：

- 构建与冷启动；每条路由可达；真实浏览器无未处理异常、无资源 404；
- 首要行动、导航、表单成功与失败、键盘操作、移动端、 reduced-motion；
- 若适用：角色权限越权负例、跨重启持久化、共享数据、上传下载、存储回读；
- 内容准确性、链接有效性、SEO 基础、隐私与第三方资产许可；
- 页面重量、请求数和关键交互性能；
- 部署前备份、版本保存与回滚路径验证。

每个承诺功能至少实际触发一次并留下可复核证据。机检全绿不能代替截图目检；发现缺陷后定位原因、修复并只重跑受影响检查及必要回归。

## 六、区分保存、发布与新网址生效

始终使用精确状态词：

- **版本已保存**：可从版本卡预览，不等于公开发布；
- **部署已成功**：部署工具明确成功且部署 URL 可真实访问；
- **网站已上线**：公开入口经过真实浏览器访问验证；
- **自定义域名已生效**：DNS、HTTPS、 apex／www 跳转与最终页面均已实测。

不要编造 URL、部署 ID、DNS 传播结果或证书状态。保存版本不是发布，发布成功也不证明自定义域名已经生效。

## 七、交付与后续迭代

交付时只报告已发生的事实，并给出：

1. 网站入口或版本入口、已实现范围与首要操作路径；
2. 技术路线、数据存储位置及浏览器本地数据限制（若适用）；
3. 验收结果、未竟项、假设、简化与已知风险；
4. 运行／回滚方式，以及域名、监测、备份和内容维护的下一动作；
5. 清理探针、测试账号、临时截图与过程副本，不将凭据或测试数据留在交付物中。

## 硬性停止条件

出现以下任一情况，停止对应动作并报告，不得造假补绿：

- 需要真实持久化却只有 `localStorage` 或 mock 数据；
- 需要真实提交、登录、支付或上传，却只有视觉外壳；
- 构建失败、核心流程未触发、关键浏览器错误或资源 404 未解决；
- 凭据缺失、权限不足、平台能力不支持或公开发布未获授权；
- 无备份且操作不可逆，或回滚路径未验证却准备高风险发布。
