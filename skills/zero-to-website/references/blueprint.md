# 网站蓝图与架构决策

在编写脚手架或页面代码前，用本清单形成一份短蓝图。内容以够执行、可验证为限，不写空泛 PRD。

## 目录

1. 产品一句话与范围
2. 信息架构与核心流程
3. 内容和数据模型
4. 技术路线决策记录
5. 设计与非功能预算
6. 域名与 URL 策略
7. 里程碑与退出条件

## 1. 产品一句话与范围

写清：

- 为哪类用户，在什么场景，完成什么首要行动；
- 首版必须交付的 1 个核心闭环与最多 3–5 个支撑功能；
- 明确不做项，以及哪些要求仅是后续候选；
- 成功指标：例如完成预约、提交有效线索、发布内容或找到文档，而非只写「页面好看」。

## 2. 信息架构与核心流程

输出：

- 页面清单：路由、页面目的、主要内容、首要 CTA、是否需要权限；
- 导航关系：首页如何到达每个核心页面，未开放入口不出现；
- 核心流程：进入 → 输入 → 校验 → 提交 → 真实处理 → 反馈 → 回读／后续动作；
- 状态清单：空、加载、错误、成功、离线、无权限、404；
- SEO／分享需求：标题、描述、规范链接、社交分享图、站点地图和 robots 是否需要。

优先保证一条主流程完整，避免先铺开大量空页面。

## 3. 内容和数据模型

### 内容

列出每类内容的来源、所有者、字段、更新频率和就绪状态。没有真实内容时可用明确标注的结构样例，不得把虚构客户、评价、数据、资质或新闻当成事实发布。

### 数据

为每类数据回答：

- 谁创建、谁读取、谁修改、谁删除；
- 是否跨刷新、跨设备或跨用户存在；
- 是否含个人信息、敏感信息或文件；
- 保存多久，如何导出、更正和删除；
- 浏览器、数据库、对象存储、第三方服务分别保存什么。

若数据只存浏览器，必须在交付说明中明确其局限；若声称云端保存，必须实际回读云端记录。

## 4. 技术路线决策记录

为每项关键选择记录「选择／理由／替代方案／代价／退出方式」：

- 静态、前端应用或全栈；
- 服务端渲染、静态生成或客户端渲染；
- 数据库与对象存储；
- 身份认证、权限模型和第三方集成；
- 部署目标、环境划分、密钥管理、日志和监测；
- 构建产物与回滚单元。

不要按熟悉度或视觉稿倒推架构。先满足数据、权限、合规与运维需求，再选择最简实现。版本号、API 和平台能力以执行时官方文档及实际工具为准。

## 5. 设计与非功能预算

锁定：

- 品牌方向：字体、色彩、布局、动效和一个可识别细节；
- 设备优先级与断点；键盘、焦点、对比度、触控目标、reduced-motion；
- 最复杂页面的性能预算：资源体积、请求数、主要媒体、第三方脚本、动画或 3D 成本；
- 浏览器支持范围、语言、时区、日期与货币格式；
- 隐私、资产许可、Cookie／分析需求和必备法律页面。

预算应可测量；不要只写「快速」「高级」「丝滑」。

## 6. 域名与 URL 策略

1. 区分平台预览地址、部署地址、平台子域名和自定义域名。
2. 域名候选应短、可读、避免商标冲突；不得把候选写成已可注册，实际可用性需查询注册商。
3. 购买域名、付费 DNS 或证书服务前取得授权并确认账户所有权；不要代收或回显凭据。
4. 规划 apex／www、HTTP→HTTPS、大小写、尾斜杠、旧链接重定向、404 与规范 URL。
5. DNS 变更前记录原记录与 TTL，保留回滚值；变更后用真实解析和浏览器访问验证，不凭「已提交」推断全球生效。
6. HTTPS 需验证证书链、域名匹配、混合内容和跳转，不以地址栏出现 `https://` 作为唯一证据。

## 7. 里程碑与退出条件

采用以下最小顺序：

1. **M0 简报通过**：核心需求、数据需求、权限与假设无歧义。
2. **M1 垂直切片**：首要行动端到端完成并可回读。
3. **M2 功能完整**：首版范围内页面、状态和负例完整，无死控件。
4. **M3 验收通过**：真实浏览器、移动端、权限、持久化与性能证据齐全。
5. **M4 可恢复交付**：版本／备份、运行说明、回滚路径和未竟项明确。
6. **M5 公开生效（可选）**：仅在授权后部署并验证公开 URL、DNS、HTTPS 与监测。

任一阶段暴露架构性错误时退回对应决策，不在错误基础上堆补丁。
