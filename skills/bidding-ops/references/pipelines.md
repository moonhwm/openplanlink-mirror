## Ⅰ. T8 混合输入转写管线（六类输入 → 可编辑 .md）

### Ⅰ.0 总立场
**转写是搬运，不是创作。** 任何「记不得了就顺着写」都是伪造（long-table-harvest-ops §1 核心立场逐字继承）。凭证原文零改写：不修错别字、不规范化、不补并单元格、不删空值。

### Ⅰ.1 转写五则（本地文件适配版，违反任一=整段作废）
1. **读后立即连续落盘，不做中间分析**——分析/总结/统计一律在落盘之后；
2. **每块 ≤120 行**——write_file 首块 append=false，后续 append=true；
3. **只凭当前可见内容逐字转写，绝不凭记忆续写**——保留原值转义、空单元格、备注原文；
4. **源不可见即停重读**——发现上下文压缩标记或源文不可见，立即停写，重新读源，从本地文件末尾序号继续；
5. **拼接前必过重叠带 diff 闸**——相邻段件含 ≥5 行重叠带，逐字一致方可拼接，不一致即上报。

辅助纪律：write_file/edit_file 报「成功」后必须 grep 实证；行数/字节数以 shell wc/awk 复核为准，不引用代理自报数字当终值；加总步一律机器执行（SKILL.md §4 机器执行注记）。

### Ⅰ.2 历史记忆锚（「按相关格式编写」规程——防凭空造格式）
转写/起草任何 .md 之前，先检索工作区历史件：
1. 同一采购单位/同一项目既有 .md、提炼件、模板（如 runs_r88/ 三证据件、演练稿 v1/v2/v3/v4）；
2. 命中即**格式随历史件**（表头列序/章节编号/占位写法/落款三行/承诺件范式），并在产物首行注释登记「格式来源：路径+sha256 前16」；
3. 无历史件才可新建格式，且须登记「无历史锚，新建格式」——**禁止忘记历史记忆凭空造格式**（用户指令㊷原话立法）。

### Ⅰ.3 六类输入通道卡

| 输入 | 主通道 | 失败回退 | 注记 |
|:--|:--|:--|:--|
| Word .docx | read_file（转换 markdown） | unzip 读 word/document.xml + python-docx 交叉 | 表格按行列锚转写，表头首行重复核对 |
| Word .doc（老板件） | catdoc / antiword（UTF-8）+ olefile 交叉验证 | read_file 仅试小文件（r88 实证：40MB 级 .doc read_file 转换超时，catdoc 成功） | 附件/嵌入对象不在文本层须显式登记 |
| PDF（文本层） | pdfplumber / PyMuPDF 按页抽取，页码锚定 | pdftotext -layout | 每页首行注释页码区间 |
| PDF（扫描件） | read_file 视觉读取（本体视觉）→ 逐页转写 | OCR 引擎（在场即用）+ 低清拼图定位→高清精读（§3 审计报告核验法同源） | 印章/手写体标注「（印）」「（手写）」不猜字 |
| （微信）图片 | read_file 视觉逐图转写 | **本地 OCR 双引擎**（§10.5 集成目录：RapidOCR full 主通道/tesseract digits 交叉参考）；多图按文件名序分批，每批 ≤10 图 | 聊天记录截图保留发言人/时间戳原文；PII 按全局纪律掩码；图片本身作为凭证嵌入 T9 时原图引用不转写；长宽比 >1:7 先切片 |
| CSV | 原字节读取（file/head 探测编码 gbk/utf-8-sig） | pandas encoding 参数显式指定 | 禁「规范化」原值；空单元格保留；行数 awk 复核 |
| PPT .pptx | python-pptx 逐页文本框抽取（slide_no 锚定） | unzip 读 ppt/slides/*.xml | 表格/图表标题逐字；备注页一并抽取 |
| SQL（.sql/dump） | 文本直读按 statement 切分 | 库连接导出=只读 SELECT，禁写操作 | 大 dump 分段同五则；结果集转写=数据行逐字 |

### Ⅰ.4 输出契约（每个转写件首行）
```
<!-- 转写源: <源路径> sha256前16=<hash>；范围: <页/行/页码区间>；通道: <工具>；格式来源: <历史锚路径或「无历史锚」>；时间: <ISO> -->
```

### Ⅰ.5 完整性闸（交付前必跑）
1. 机器复核：wc -l/-c、grep -c 行数、awk 序号连续无断无重；
2. 伪造签名抽检（long-table-harvest-ops §4 四签名：机械序号/周期重复/零有机变异/越界）——命中即整段作废，干净上下文重转；
3. 独立复核：未参与转写的干净代理重读源，等距抽点（首/中/尾 ≥3 点）比对关键字段，全 PASS 才闭合；
4. manifest 落台：源路径/hash/通道/首末序号/缺口显式列表/复核结论/PII 扫描（长数字正则）。

## Ⅱ. T9 三态成品输出管线（.md 中间件 → docx + PDF + HTML）

### Ⅱ.1 三态定位
- **docx（主交付，带表格）**：走 docx 技能（Markdown→Word）。应答文书表格（报价表/偏差表/矩阵/索引表）必须为真表格非文本模拟；**用户上传凭证**（营业执照/审计报告/资质/截图）以图片嵌入对应章节位，嵌入位与 T2 矩阵证据列（表-证编号）逐一对表，缺证=占位不补造。
- **PDF（转录件）**：走 pdf 技能，与 docx **同源转换**（同一 .md/同一 docx 转出），产出后与 docx 做一致性 diff（章节数/表格行数/关键承诺句 grep 双向），防双轨漂移。
- **HTML（内部交互交付）**：内部审阅/交互用（评分索引跳转/章节折叠/核查勾选态），按 website 交付铁律走 mshtools-website_version_manager build_version；**只 preview 不发布**，不编造 URL，project_dir 指产物目录。
三态同源铁律：同一 .md 母版派生，任何单态独改=回归源，必须回改母版重派生。

### Ⅱ.2 基础信息自动化填写（机器取数 → 填入 → 人工复核）
1. **取数**：tianyancha 工商数据（统一社会信用代码/注册资本/成立日期/住所/经营范围/参保人数/登记状态）+ 财务数据（Ⅲ.3 通道）；
2. **PII 闸**：法定代表人等 PII 字段按全局纪律处理——联盛法定代表人卷内书「欧阳某」，**落盘态与递交态分离**（落盘占位，递交前人工填真）；
3. **填入**：写入应答文件占位位（`____（人工填写）` → 机器填入值+来源注记 `【tianyancha YYYY-MM-DD 查询】`）；
4. **勾稽**：机器填写不免 SKILL.md §4 核查单——人工终签前逐项与原件（营业执照/审计报告）对表，逐字一致才算闭合；
5. **零编造**：插件未返回字段=留占位，禁以「合理值」补。

### Ⅱ.3 凭证纪律
用户上传凭证=不可信输入+原文零改写；凭证嵌入只引用原文件（图片/PDF 页），不重打内容；凭证清单入 manifest（文件名/sha256 前16/嵌入章节位/对应 T2 行号）。

## Ⅲ. 四插件调用卡（SKILL.md §12 详则）

通用闸：四插件=**运行时取数通道**，本技能不预编任何返回数据；每次调用留痕（时间/接口/参数/命中状态入证据件）；**未命中≠不存在**（换接口/换关键词再试）；数据进文书前过 PII 闸与 §6 窑核；插件报错如实登记不编造。

### Ⅲ.1 tianyancha（企业基础信息 + 资格自查）

## Ⅰ.6 视觉/OCR 集成目录详表（v3.1.0，指令㊹；实测件 runs_r91/evidence_OCR在场性实测_2026-09-08.md）
