## §0 定位终裁（v1.2，三部曲效能试验收敛证据）
- 本件是**编排层作业纪律清单**（主线程/调度者的工作流），**禁止以 prompt 注入或流程强制方式投喂池模型**——实测：知识注入效应与零不可区分（三轮符号翻转，噪声地板 ±2 分）；五步流程强制注入 = −6.0 显著负效应（填表合规诱发预算坍缩）。
- 正确用法：由编排者按 §1-§6 逐项执行并留痕（五查表→公式计算→核查单→情景模拟→窑核），把技能转化为可审计的工作流，而非知识补丁。
- 效能测量规程（效能轴两律）：①效能声明必配安慰剂臂；②≥3 轮/格重复（噪声地板 ±2 分/轮），未达即标「不可测」。

## §1 评分规则五查（拿到采购文件先做，条款承载律）
0. **第 0 查=自查（v2.2.0 增，对抗对称性）**：投前先查我方自身——对手会用同样的五查查我们。项：工商登记状态/司法案件标签/社保参保状态/资质有效期/历史履约与中标公示（首单挂账：联盛「司法案件」标签自查明细）。前置两问（analyze-tender 第 0 步）：①投标主体是哪个？②电子标还是纸质标？——招标文件缺失时转**引导式问答模式**（逐项问资格条件/评分标准/实质性条款/投标文件组成），禁止凭空白猜。
1. **评审比较对象**：加成还是总价？定位消歧条款原文（如「评审比较的是加成数值」）；**缺失即一级风险**——实测：省略该条款+给出总价数字，六池模型 100% 翻转口径。禁用总价示例辅助理解。
2. **基准价形成**：最小值/均值/次低/是否下浮；均值基准利于高分投标人但抬采购价。
3. **扣分系数与封顶**：每 1% 扣 c 分、封顶 cap；记算封顶触发点与「封顶永不触发」判据（支撑下界）。
4. **非价格分结构**：各项分值、加分上限、商务分总分截断（如 17→10 封顶）；识别可顶格项。
5. **份额与合同一致性**：评标办法份额（如 50/30/20）与合同条款（如「一主一辅」）是否张力。

## §2 公式库（references/formulas.md 详证）
- 总得分：`S_i = NP_i + P_max − min(c·100·(p_i − p_min)/p_min, cap)`
- 反超充要（对手 j 最低报价 p_j < p_H）：`c·100·(p_H − p_j)/p_j > NP_H − NP_j`
- 临界通式：`p*(NP_j) = c·100·p_H / (c·100 + (NP_H − NP_j))`；整数规则：非整数取 ⌊p*⌋、整数取 p*−1
- 护城河点导数：`dp*/dNP_j = c·100·p_H / (c·100 + D)²`，D = NP_H − NP_j（m≈250、c=0.7、p_H=260 时 = 625/182 ≈ 3.4341 元/吨/分）
- 每 10 元价差扣分 = `1000·c/m`（m=基准价）

## §3 非价格顶格策略
账期（响应月数顶到加分上限）/ 到货（优于要求天数）/ 财务（负债率档位 + 现金流全正，审计报告扫描件核验法：低清拼图定位+高清精读+勾稽交叉）。顶格锁定后：对手 NP 每少 1 分须多降护城河系数×1 元/吨——把非价格诚意换算成价格缓冲，再定报价。

## §3.5 策略推演模板（报价优化三步）
1. **定结构**：先判基准价类型（最小值→低价者满分；均值→低于均值者满分）与份额结构（独得→价格权重极端化，宜激进；分标→保排名弹性）。
2. **找临界**：列出反超/被反超临界式（§2 F2），对每个候选对手算临界报价；独得份额下，第一名与第二名收益差=全部份额，价格让步的边际收益最大——把报价压到「刚好不被任何合理对手反超」的临界上方。
3. **做取舍**：每降 X 元/吨的边际扣分（§2 F5）vs 反超概率变化，选期望份额×份额值最大者；给不出概率时，给「临界价位清单+各自失守条件」而非拍脑袋报价。
## §4 形式风险核查单（一票否决性质）+ 写作侧防线（签署前必跑）
①承诺函/落款名称=公章=营业执照**逐字一致**（缺字=可废标实锤案例）；②签署日期 ≤ 递交截止日（晚于截止=逻辑风险实锤案例）；③授权链完整（件数与采购文件要求逐一对表）；④扫描件印章清晰；⑤份额规则与合同文本张力登记。处置：主动补正说明+重签盖章件+递交时序说明+回执。
**写作侧前置**：文书起草时即逐项落 □ 勾选记录随稿归档；应答矩阵「自查状态」列不得留空（留空=未完成）；范式见 §8 T3，三审核查见 §8 T4。
**机器执行注记（v2.2.0）**：凡条数/分值/合计**加总步一律机器执行并留痕**（手算加总=已登记失败模式「加总失明」）——T4 审核表条数、T2 矩阵行数、模拟评分合计均适用。

## §5 情景与模拟（无分布不断言）
定性概率断言（「大概率第一」类）**必须**改为：明示分布三件套（对手数/报价分布/NP 分布）→ 精确枚举或 ≥10,000 次模拟（固定种子）→ CI 报告 → 分布敏感性声明（哪条结论对哪个假设敏感）。机制比较用反事实（系数/基准/封顶/份额变体）。期望值只报模拟值+口径（如「评审直接比较加成」vs「P=100+m」，口径差如实给）。

## §6 数值窑核纪律
关键数值双管验证（第二模型/独立脚本复算）；**结论行 vs 推导体一致性必查**（有模型结论行四次背叛推导体）；嵌套材料先剥元评论再评；高置信度自报不免窑核（反转出题局：陷阱题下置信度与正确率脱钩，100% 自报照落阱）；代码级根因断言须机器执行验证后方可定稿。
**失败模式三型**（负载梯度局，窑核定位用）：①条款/规则误读=外生文本型；②系数回退=上下文追踪型（题面已改系数仍用旧值）；③结论-推导解耦=输出架构型（推导体正确而结论行背叛）。

## §8 文书模板族（分析→写作直通）
模板全文在 [references/templates.md](references/templates.md)（前沿池起草+窑核+判官席抽核轨迹在案），六件套：
- **T1 三册制应答文件骨架**（商务/技术/报价 21 章）：按采购文件目录逐章映射；[实证]章=案例验证高危章（授权/财务/点对点应答），[通用范式]章=常规章。
- **T2 点对点应答矩阵**：评分办法/合同条款每项要求必须入行（条款编号/要求摘要/响应/证据材料/页码/自查状态）；**无行的要求=漏答风险**，正偏离须附证据页码。
- **T3 承诺函与补正文书双范式**：范式A=签署前强制自查版（内嵌 §4 R1/R2 自查行）；范式B=补正说明（风险触发后处置：笔误事实/原因/补正件清单/时序说明）。
- **T4 标书质量审核表**（三审制，v2.2.0）：资格/符合性/废标/评分项/★▲条款**原文逐条填入不得遗漏**；负责人与审核人独立双份制作合并定稿；条数加总机器执行；审核列留空=未完成。
- **T5 文书工艺章**（v2.2.0）：评委阅标五步行适配——评分索引前置/信号词同措辞/配图加分/对照表/模拟评分表（verifier 前置闸，交付前必跑入 runs）。
- **T6 标准承诺条款库**（五类，v2.2.0）：质保/验收配合/数据保密/知识产权/售后分级响应——过可验证性梯度（可查证承诺留、空泛承诺改）后套用。
使用规程：先按 §1–§5 完成分析与报价推演（§1 含第 0 查自查+两问前置）→ 按 T1 搭骨架 → T2 逐条填矩阵 → T3/T6 起草承诺件 → T5 工艺适配 → T4 三审核查+模拟评分 → §4 写作侧防线逐项 □ 勾选 → 人工终稿签发。模板族按 §7 炉迭代（前沿池起草→校验窑→判官席→verifier 门），三件套轨迹缺一不升级。

## §8.5 T7 同系迁移与国标细化管线（v2.3.0，用户指令㊵定编）

公告信息不足以填满技术册时，按四拍执行（源 r88 宏华角件实战）：

1. **拍1 公告五查**：照 §1（含第 0 查+两问前置），公告可执行条款全入 T2 矩阵，缺失层（评分办法/技术规格书/应答组成）显式登记「待采购文件核」，禁止凭空白猜。
2. **拍2 同系历史迁移**：检索工作区内**同一采购单位**的历史采购文件与本方历史应答正本，提炼三件：①评审范式（比较对象/基准价/扣分系数/非价格分结构——同采购人风格高度可迁移，但须标注「历史范式，本项目以新采购文件为准」）；②资格条款版本差双向对照（历史有而新无/新有而历史无，逐条列表）；③历史正本工艺与瑕疵实录（可复用工艺编 A 系、规避教训编 B 系，如：索引表前置/偏差表按章响应+兜底句/自拟承诺函补强评分关联条件/表-证编号证据链/占位保序；空挂节/报价说明留空/落款漏字/目录编号混乱）。
3. **拍3 国标调用**：标的→产品标准+材质/检测配套标准；经 china_standards 插件实时检索核验**现行/废止/替代链**（禁凭记忆引标，废止版引用=形式事故）。引用三铁律：①只引编号+名称+现行状态+实施日期；②**标准具体数值零臆造**（公差/强度等指标一律「以标准全文及技术规格书为准」）；③检索留痕（时间/通道/关键词/命中状态入证据件）。
4. **拍4 细化落点**：技术册产「国标执行矩阵」（维度×执行标准×应答承诺×规格书参数位×偏离）；检测能力按国标检验类别填框架；质保承诺引标（编号+名称+现行状态）；偏差表双轨（对外按章响应+兜底句 / 内部逐条款矩阵）；自拟承诺函补强评分关联商务条件（落款名称与公章逐字一致自查前置）。

门禁：资格张力（如主体身份与「不接受代理商」类条款冲突）**只登记不报方案**，裁决权在用户；PII 按全局纪律脱敏；一切企业事实占位人工填；管线产物标签「模型能力上限参考」。

## §10 T8 混合输入转写管线（v3.0.0，用户指令㊷定编；详则 references/pipelines.md Ⅰ）
投标素材转写（本地 Word/PDF/（微信）图片/CSV/PPT/SQL → 可编辑 .md）按搬运纪律执行：
1. **总立场**：转写是搬运，不是创作——继承 long-table-harvest-ops §1 五则（读后立即落盘/每块 ≤120 行/只凭当前可见逐字转写绝不凭记忆续写/源不可见即停重读/拼接前重叠带 diff），引用不复制；凭证原文零改写（不修错别字、不规范化、不补并单元格）。
2. **历史记忆锚**：转写/起草前先检索工作区同采购单位/同项目历史件（提炼件/演练稿/模板），**格式随历史件**并登记格式来源（路径+sha256 前16）；无锚才许新建格式——**禁止忘记历史记忆凭空造 .md**（指令㊷原话立法）。
3. **六类输入通道卡**：见 pipelines.md Ⅰ.3（.doc 大件 catdoc/antiword+olefile 交叉——r88 实证 read_file 超时回退；扫描件走视觉通道+低清拼图定位；（微信）图片保留发言人/时间戳原文+PII 掩码；CSV 原字节禁规范化；PPT 页码锚定；SQL 只读）。
4. **输出契约**：首行注释登记转写源/hash/范围/通道/格式来源/时间；完整性闸=机器复核行数+伪造签名四签名抽检+独立复核抽点 ≥3+manifest 落台。

### §10.5 视觉/OCR 集成目录（v3.1.0，用户指令㊹定编；详表 pipelines.md Ⅰ.6）
（微信）图片与扫描件识读的本地化通道目录，三原则：**待高保证**（在场性逐环境实测登记后方得正式凭证转写依赖，实测件=runs_r91/evidence_OCR在场性实测_2026-09-08.md）、**内包含**（能力内化为 T8 管线环节，编排层调用，不构成对外运行时依赖）、**不引用**（标书成品与交付件中不得出现工具/技能/通道名，只见转写结果与 conf 标注）。
- **vision-ocr-pipeline**：主通道=RapidOCR full（本环境实测 4/4 全对，定档**高保证·在场可用**；新环境须重装 rapidocr-onnxruntime）；tesseract digits=数字字段交叉参考（有尾噪声实证，须 rapid 互验）；长宽比 >1:7 先切片；字高阈值继承该技能（引用不复制）。
- **doc-image-solver**：`transcription_qa.py` 七项机检挂 T8 完整性闸（自检 PASS）；手写/歧义逐条【存疑】禁猜读。
- **qr-visual-rescue**：本环境**降级在场**（自检仅 opencv 单库）——清晰 QR 可解，疑难件登记「未解出」不硬闯；标书场景低频，补齐三库后复测升级。
凭证级图片（执照/审计报告/截图）转写后**必须**按 §11 人工勾稽原件逐字对表，OCR 文本 conf 最高记 estimated。

## §11 T9 三态成品输出管线（v3.0.0；详则 pipelines.md Ⅱ）
应答文书终态交付=**同一 .md 母版**派生三态（单态独改=回归源，必须回改母版重派生）：
- **docx（主交付，带表格）**：走 docx 技能；表格为真表格；**用户上传凭证**（执照/审计报告/资质/截图）以图片嵌入章节位，嵌入位与 T2 证据列（表-证编号）对表，缺证=占位不补造。
- **PDF（转录件）**：走 pdf 技能同源转出，与 docx 一致性 diff（章节/表格行数/承诺句双向 grep）防双轨漂移。
- **HTML（内部交互交付）**：内部审阅用（索引跳转/折叠/勾选态），按 website 交付铁律 build_version 只 preview 不发布、不编造 URL。
**基础信息自动填写四步**：机器取数（§12 tianyancha/财务通道）→ PII 闸（法定代表人卷内书「欧阳某」，落盘态与递交态分离）→ 填入（带来源注记）→ 人工勾稽（机器填写不免 §4 核查单，逐项与原件逐字对表）；插件未返回字段=留占位，零编造。

## §9 版本管理条款（膨胀抑制立法，v2.1.0 起生效；经 mm3 窑核修订 v2）
1. **语义化三档**：
   - **major（X.0.0）**：结构重排/技能合并/触发域实质变更（例：章节体系重排、两技能合一、触发词域增删）——重打 .skill 双落+广播+请用户换装；
   - **minor（x.X.0）**：新公式族/新模板族/新章节/新实战场景定编——重打 .skill 双落+广播一次+请用户换装；
   - **patch（x.x.X）**：座席档案更新/台账措辞/日期戳/错别字——可重打 .skill 双落，但**严禁广播、严禁催换装**，积压随下次 minor 一并交割。
2. **同日合并律**：同一自然日多次 patch 级变更合并为一次落盘一次 bump；minor 一日不超过一次（结构冲动隔日冷静期）。**豁免**：用户当令点名、白名单②缺陷修复不受冷静期与同日一次限制（已知缺陷不留窗口期）。
3. **变更触发白名单**：可 bump 事由仅三类——①实战/回测新证据需定编（changelog 行须附证据件路径）；②缺陷修复；③用户指令。多事由并存取最高档处置。禁止「措辞润色」式无证据 bump。
4. **留痕**：任何版本变更须头部 changelog 一行（版本号/日期/round/事由，只增不删；勘误=追加 supersedes 行，不删原行）+ verifier 门记录。**两次 minor 之间的 changelog patch 行即积压队列**，换装时逐行核对并入。
5. **缄钥席对齐口径**：权威件=/mnt/agents/output/bidding-ops（双落 upload）；用户技能位只读，落后即于 changelog 标注「漂移 vX→vY」（不依赖广播），随 minor 以上换装一次到位；研究/实战一律以权威件最新版为准，禁止引用漂移位旧版条款作答。
6. **溯及登记**：2026-09-06 一日五代（v1.1→v1.3→v1.4→v2.0→v2.0.1）登记为膨胀反例；其中 v1.3/v1.4/v2.0 属白名单①②③，v2.0.1 实应 patch 静默——此后 patch 级一律静默。
