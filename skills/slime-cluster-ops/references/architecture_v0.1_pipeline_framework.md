## 一、升格动机：从终端路由试点到集群管理框架

r67（声明穷举，2026-09-08）将黏菌组网三拍定义为终端项目路由试点规程：

| 黏菌阶段 | r67 原始定义 | 在案实证 |
|---|---|---|
| ①铺菌毯 | 候选池穷举，同域多工具并存不预设淘汰 | r65 浏览器/解析器多路线并存 |
| ②营养流观察 | 实战任务=营养源；逐路径记通量/成本/事故率/幻觉率，台账留痕 | r64 席级营养流测绘 |
| ③路径收缩 | 路由表收敛：主路径+备用+禁用登记；**萎缩≠删除，进休眠登记可再激活** | r66 obscura 成为抓取主路径 |

r68（2026-09-08）完成三拍首次全程实战闭合：菌毯（8 站×3 解析器）→营养流（N1–N5+T1–T7 台账）→收缩（主路径 1+可用 1+禁抓 6+休眠 2）。

**升格主张（v0.1 核心）**：同一三拍同样适用于 K3 集群三层的管理——技能不是「装好就一直在场」的静态资产，而是**有通量、有成本、会萎缩、可休眠、可再激活**的管路网络。r74 E2 MCPM 证据场仿真给出反向警示：稳态呈「簇内密、簇间断」，分散通路不会自发连成主干——**主干成形必须有台账驱动的主动收缩，不能等它涌现**（r74 诚实结论，conf 高）。这正是本框架存在的理由。

## 二、三拍的集群级映射

### 第一拍 铺菌毯 = 同职多通道冗余池设计

定义：同一职责域至少维持 ≥2 条可调用通道，并存不预设淘汰；通道间**异构**（不同上游/不同技术栈）优先于同构多开，异构才抗共因失效。

在案冗余池（实读证据）：

| 职责域 | 通道池 | 证据 |
|---|---|---|
| 网页抓取 | obscura（主）/ Lightpanda（休眠备用，AGPL 待评估）/ camoufox（风险登记：作者失联前例）/ Playwright-CDP（重装备用） | r67 §二 |
| 金融数据（A 股优先） | agent-gw 系 **wind / ifind / gildata / yahoo** 四通道在案；caixin 通道登记为扩展候选（待台账积累） | r67 §二；caixin 为本函用户口径登记 |
| QR 解码 | **七库开源梯子**（opencv/zxing/wechat/qreader/PyBoof/zbar/quirc）+ Dynamsoft SDK + CamScanner 商用增强通道——r96 全装全测在案 | pipelines.md §Ⅰ.6 行（runs_r94/r96 广播与台账） |
| 文档 OCR | rapidocr（主通道）/ tesseract chi_sim（补装后定档**交叉参考**，错字率高于 rapid）/ CamScanner OCR（商用，OAuth 已通）/ 豆包通道（**未在实读材料中实证，登记为候选，待台账积累**） | runs_r93 广播 5；runs_r96 台账 |
| 标准/法规情报 | china_standards 通道（r68 std.samr/openstd 双主路径实证）；yuandian_law、tianyancha 通道在插件族登记 | r68 §三；r67 §四 |
| 判官池（子代理层） | 4 判官检出率 0.9/0.7/0.5/0.3 异质池（仿真在案） | r74 §三 |

### 第二拍 营养流 = 调用台账驱动的通量计量

定义：每次实战调用=一次营养注入；逐通道记通量（成功件数/字节量）/成本（池耗票、时延）/事故率/幻觉率，全部落台账留痕。

**对接既有台账**：
- `runs_r94/ledger_r94.jsonl`（19 行实读）：字段模式 `{"ts","run","act","detail","conf"}`，conf 取 verified 等档。本框架沿用此 schema，不另造格式。
- 谷票账（MyTan 科研经费台账）：r74 已示范「600 票建账／本轮自律 ≤30 票／名义估耗 vs 账面口径差登记 note 行」的记法。

**通道级通量快照 v0.1 字段设计**（每条 jsonl 一行，per 调用）：

```json
{
  "ts": "2026-09-09",
  "run": "r97",
  "pool": "qr_decode",            // 冗余池 ID
  "channel": "zxing",             // 通道 ID
  "act": "decode",
  "target_class": "实拍点单码",     // 任务类别，脱敏
  "result": "decoded|miss|error|refused",
  "flux_bytes": 0,                 // 有效产出字节
  "cost_tickets": 0.0,             // 池耗（谷票账口径）
  "latency_s": 0.0,
  "incident": null,                // 事故登记（OOM/段错误/授权失败等）
  "drift_note": null,              // 环境漂移观察（§四）
  "conf": "verified"
}
```

**当前三个在职冗余池的通量快照（实读在案，非推算）**：

1. **QR 解码池**（r94 实战，ledger_r94.jsonl 行 1）：20 件实拍点单码三库批量——19/20 decoded（opencv 14／zxing 救 4／wechat 救 1），1 件远景屏摄未解出。通道互补性实证：zxing/wechat 是 opencv 的净增量（conf: verified）。萨莉亚绿码件：七库+商用增强+拉正扫掠全灭，定案=信息物理丢失，唯一解=重拍/NFC（runs_r96）。
2. **OCR 池**（runs_r93 广播）：tesseract chi_sim 补装复测中文链路通，错字率高于 rapidocr——路径收缩**已完成一例**：rapid 主通道维持，tesseract 定档交叉参考。
3. **金融数据池**（r67 §二登记）：wind/ifind/gildata/yahoo 分域主路径在案，A 股优先 ifind/wind/gildata；**逐通道成功率/成本/事故率尚无逐调用台账——待台账积累**（v0.1 只立 schema，不补造数字）。

### 第三拍 路径收缩 = 休眠/退役/再激活规程

r67 关键纪律原样升格：**收缩不是删除**——萎缩路径进入「休眠登记」，主路径失效时可再激活（对应 H1 单开发者失联预案）。

在案先例（实读）：
- Lightpanda 休眠备用（r67 §二，AGPL 传染性待评估）；
- stdlib robotparser 休眠=「N1/N2 双缺陷登记，**永不用于守门判定**」（r68 §三）——休眠可附「限定再激活条件」或「用途收窄」；
- terminal-route-pilot-ops 候选技能待命（r67 §五：仅登记不建，待 ≥2 域完整三拍循环——现有浏览器/QR/OCR 域实证，建技能与否仍待用户拍板）；
- obscura v0.3.0-candidate 静默积压（r67 §三嵌入裁定：用户拍板换装前不催）。

**收缩判据草案（v0.1 提议，未经实战校准，标注 conf 低-中）**：

| 判据 ID | 触发条件 | 动作 | 再激活条件 |
|---|---|---|---|
| S1 连续败北 | 同类任务连续 N=3 次 miss/error 且同池他通道成功 | 降档：主→备用 | 主通道失效时自动回池首测 |
| S2 共因失效实证 | 一次事故波及 ≥2 通道（如环境漂移同灭） | 事故登记+装栈规程复审 | 复测证据件落 upload 后 |
| S3 上游失联/停维 | up-distill 情报确认作者失联/仓归档 | 风险登记→休眠（camoufox 先例） | 上游复活或 fork 出现 |
| S4 合规降级 | 守门判定不可信/许可证风险升级 | 用途收窄或禁用登记（stdlib robotparser 先例） | 缺陷修复实证 |
| S5 成本倒挂 | 单位通量成本持续 >池内中位 2×（需 ≥10 次样本） | 降频观察一个周期 | 成本回落或任务结构变化 |

**N=3、2× 等阈值均为草案起点，无实证依据，须在台账积累后校准（诚实声明）。**

## 三、环境漂移免疫设计（三次漂移实证的框架化）

实读在案的三次漂移教训（runs_r94 广播 73/74、ledger 行 16）：

1. shell 各调用间包状态可漂移（zxing 装了又消失）→**环境敏感操作必须同一 shell 调用内完成**；
2. opencv 版本在 4.10/4.12/5.0 间漂移三次（qreader 依赖带回 opencv-python 5.0 实锤）→规程=**uninstall 全族→锁版装→同一调用内跑批+断言版本**；
3. r97b：npm 包+钥匙串同灭（第三次实证）→**备件位 upload 持久层**制度化。

框架化条款：

- **D1 备件位持久层**：重资产（模型权重、jar、so、tessdata）一律备件位 upload/cross-ai-toolkit/（在案：wechat_qr_models、esdnet 41MB、tessdata 2.47MB、qreader_weights 24MB）；热拔插环境只装轻量壳。
- **D2 同调用内装栈断言**：装包+版本断言+跑批三段必须在同一 shell 调用内；跨调用一律重新 self-test（qr_multi_decode `--self-test` 先例入法）。
- **D3 内嵌优先律**（r95 指令㊽入法）：小脚本 vendored 入技能包体自包含（bidding-ops 6 件 ~35KB 先例）；重资产走 D1。
- **D4 漂移观察入台账**：每次版本漂移在 ledger `drift_note` 字段留痕，构成 S2 判据的输入。

## 四、与判官池 SMA 权重的接口（E1c 复验挂点）

r74 E1a 实证（自证伪，判例败露学第四例）：SMA 原式 W 作判官权重 **0.845±0.064 劣于等权 0.877±0.050**；机理=W 是位置更新探索步长权重、非质量排序权重；修正=排名精英半群（前半 1.4/后半 0.6，0.884±0.051，微弱不显著），挂账 E1c。

runs_r97 SMA 一手 FGCS 核验（evidence 件，2026-09-09）收口：书志 FGCS vol.111 pp.300-323, DOI 10.1016/j.future.2020.03.055；r74「语义误读」一手成立（conf 高）；**三坑口径**为 E1c 复验的强制实现约束：

1. **log10 坑**：论文印 log 未标底数，官方 SMA.m（L76-84）与第三方复现均为 **log10**——复验必须按 log10；
2. **负分支坑**：W 双分支——前半 1+r·log10(...)，后半 1−r·log10(...)；只实现正分支=改了算法；
3. **括号层级坑**：位置更新为 vb·(W·XA−XB)，**W 只乘 XA**；错写 vb·W·(XA−XB) 数学上不等价。

黏菌框架挂点：判官池本身也是一个冗余池，适用同一三拍——菌毯=异质判官并存；营养流=逐判官检出率/误报率/Q 值台账；收缩=S1–S5 判据同样可用于判官降档。W 动力学只作**权重启发式**使用，引用须带批评注记（Camacho-Villalón 2022 / Rajwar 2025 Table 2 列 SMA「无效隐喻+结构性偏置」/ Sörensen 2015），不作性能主张。z=0.03 强制随机复核条款在案（SMA.m L55，原文 §3.4 敏感性实验选定），判官池化待 E1c。

## 五、边界与不可让渡

1. 本框架是**管理框架声明**，不是新技能；不创建/修改任何 SKILL.md；terminal-route-pilot-ops 等候选件维持「仅登记待命」。
2. 主权/灰度纪律沿用 r67 §〇：主权=沙盘纪律层；灰色=合规自守门自建；红线原样不动（robots 谨慎拒绝优先、不绕登录墙、禁外发项目内容等）。
3. 本框架不编造任何调用统计：金融数据池通量、豆包 OCR 通道、caixin 通道均为登记/候选态，数据**待台账积累**；S1–S5 阈值均为草案。
4. 任何通道的装卸/换装逐次批准；静默积压不催。

## 六、本轮 top3_likely_wrong

1. 三拍从终端路由向「技能舰队+子代理池」的可移植性系类比推演；E2「簇间断」仿真反而提示主干需主动管理，但**主动收缩在技能层尚无完整循环实证**（QR/OCR 两例是通道级不是技能级）——conf 中。

3. 金融数据四通道「冗余」系登记在案口径，四者行情覆盖与字段口径是否真互补（可互为备胎）未经对撞实测，可能存在名义冗余实际同源——conf 中。
