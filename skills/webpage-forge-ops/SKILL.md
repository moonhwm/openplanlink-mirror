> 立法锚：**「网页由代码渲染产出，经验由技能承载复用——先核查案例，再沉淀规程，后注造页面。」**

## 核心方法论（一句话）

案例核查（证据分级）→ 经验卡（制作路径+参数+坑位）→ 规程注造（单文件 HTML 优先）→ 版本交付（website_version_manager），四环缺一不动工。

## 工作流

1. **案例核查**：对参考案例做证据分级——代码匹配/提示词展示/创作者账号三级；「一句话生成」类宣传必须核查隐藏输入（素材清单、预置 skill、内部循环次数），不得仅凭成片外观推断制作方式。拆解动作=把案例逐项对照四路径分类法（references/production-paths.md）归类到路径并摘出证据锚；证据不足（仅宣传截图）→ 中断本管线，不进经验卡，不注造页面；本件对此类输入的产出形态=「灵感参考登记条」一条（案例锚一句话+可见视觉元素清单+「非工作流依据」标注），交付用户后管线即收官，后续视觉参考归 musepool 域。
2. **经验卡**：每个案例落一张卡，字段与填卡纪律按 references/experience-card-template.md 执行（案例锚/证据级/制作路径/可见输入/隐藏输入/成本口径/失败返工/可复用要点/核查人与日期，九字段不齐不称为卡）；制作路径四分类见 references/production-paths.md。
3. **规程注造**：按经验卡选路径写页面——默认单文件 HTML（零外部依赖、file:// 可开）；数据类页面每数字可钻取来源——「可钻取」=页内来源铭文（脚注/标注/悬停注明出处与截点），零外部依赖下单文件内即可实现，不要求外链；设计先过反 slop 纪律——本地最小检查清单（musepool 缺席时可独立执行）：①不堆渐变紫/圆角卡片默认美学；②视觉语言先定一句话（风格锚+配色锚+字体锚）再动工；③排版有编辑意图（留白/层级/节奏），非组件平铺；④每屏只一个视觉主角；⑤交付前自问「这像模板生成的吗」，像即返工。
4. **🔴 自检三问**（附机检钩子，按产物形态分支）：①信息来源都标了吗——数字/图表块与来源铭文须一一对应（`grep -cE '来源|出处|截至' page.html` 计数 ≥ 页面数据块数，不足即人工逐块补标；铭文在页内，零外链依赖）？②无编造数字/假链接吗（`grep -noE 'https?://[^"'\'' ]+' page.html` 逐一可达或标「示意」，无链接是合法形态）？③路由可达吗——纯单文件 HTML 形态：`grep -oE '(href|src)="[^"#][^"]*"' page.html` 不得指向不存在的本地子页（多页则每页须从 index.html 链达）；React 形态（仅当产物来自 webapp-building 链）：强制 hash 路由或首页内导航，`BrowserRouter` 仅可出现在脚手架自带 main.tsx。
5. **版本交付**：先 `mkdir -p /mnt/agents/output/app` 并以 touch 探活（目录不可建/不可写 → 产物落 `/mnt/agents/output/` 根目录并显式声明「预览降级，无 version 快照」）；可写则拷入后调 website_version_manager（html 类型=纯 HTML 目录，project_dir 指含 index.html 的目录；后端=dynamic）。React 项目的脚手架搭建不归本件（归 webapp-building 链）；若页面产自该链，本件只管其交付纪律：先 npm run build，type=static、project_dir 传项目根（非 dist），并强制 hash 路由/首页内导航。只展示其返回的 URL，且仅在返回成功时展示；若用户回报 404/空白，重存至多一次（稍候再试，不连续猛刷），仍失败则如实告知「快照已成、平台预览侧故障」，不反复重建、不展示失效链接。数据持久化需求如实声明「纯前端数据只存在用户浏览器」，禁把 localStorage 说成真实持久化。

## 失败模式（if-then）

| 触发 | 一线处置 | 兜底 |
|---|---|---|
| 参考案例只剩宣传截图，无工程披露 | 中断管线：经验卡证据级标「创作者账号级（未独立核实）」，不进方法论 | 降格为灵感参考：仅可复刻可见视觉元素并标注「非工作流依据」，不得声称还原制作路径 |
| 页面需跨访问留存数据（账号/提交/订单） | 判为全栈需求，转 webapp-building+backend-building 链；交付阶段回本件第 5 步纪律（dynamic 类型+URL 处置闭环） | 用户坚持纯前端 → 显式声明数据仅存浏览器 |
| website_version_manager 返回 404/空白 | 重存至多一次（间隔稍候，不连续猛刷） | 仍失败则如实告知「快照已成、平台预览侧故障」，稍后重试，不反复重建、不展示失效链接 |
| /mnt/agents/output/app 不存在/不可写 | mkdir -p + touch 探活前置 | 产物落 /mnt/agents/output 根目录并声明「预览降级，无 version 快照」 |
| 「一句话生成」诉求但隐含复杂素材 | 列出隐藏输入清单请用户确认 | 拆成多轮：先素材后页面 |

## 诚实边界

- 本件管「经验→规程→注造」的管线纪律；与 rumor-chain-verifier 的切分：本件工作流第 1 步只做**证据分级**（案例有无工程披露、披露到哪一级），不做真伪定断；「这案例是不是造假/洗稿/AI 幻觉」的定断归 rumor-chain-verifier，引用不复制。
- React 边界：本件不搭 React/全栈脚手架（归 webapp-building/backend-building 链）；对已产出的 React 页面，本件只施加交付纪律（static 类型、hash 路由、/ 可达），不替代其脚手架规程。
- 四路径分类法源自公开案例核查仓库（awesome-opus-5-5-videos，2026-09-25 截点版），分类边界以证据为准，不为「一句话神话」站台。
- 纯提示词/工作流型技能：无 scripts/，自检以 dry-run 用例集替代（见下）。

## 自检（dry-run 用例集）

`references/dryrun-suite.md` 三用例：①「照这个爆款视频页给我做一个」→ 应先核查证据分级而非直接开写；②「做个能注册登录的落地页」→ 应判全栈并声明持久化边界；③「数据看板网页」→ 应要求数据来源并保证每数字可钻取。逐项核对预期行为。闭环方式：每次实跑或评审后把结果（通过/偏离+处置）追加进该文件「复核记录」节，形成用例集↔实测的反馈回路。

## Runtime 中立

产出物为浏览器可开文件；交付一律经 website_version_manager，仅展示其返回 URL，不自造链接。
