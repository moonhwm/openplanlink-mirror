# xunlei-share-verify 迅雷分享核验

## §0 铁律（先读）

1. **零编造**：清单只来自实测抓取的页面或用户提供的文件；抓不到就写「未获取」，禁止凭 URL 或文件名样式推测内容。
2. **失败如实报告**：链接失效、提取码错误、登录墙、滑块/验证码、地域限制——记录现象与页面证据，当轮停止，不无限重试，不输出任何推测性清单。
3. **提取码最小化落盘**：pwd 只用于当次访问，不写入报告正文与任何交付文件。
4. **下载需明示**：默认只做清单级核验；逐文件下载+哈希校验须经用户明确同意，且先报总体积再动手。

## §1 收件（开工前一次问齐）

缺项可开工（降级为仅清单建档），但必须标注「未提供」：

- 分享链接（必需，形如 `https://pan.xunlei.com/s/XXXX`，可能自带 `?pwd=` 或用户另给提取码）
- 比对基线（三选一或全无）：
  - a. 期望清单文件（txt/csv/json，历史导出或发布方原始列表）
  - b. 本地目录快照（上传 zip 或逐条粘贴文件名）
  - c. 哈希表（SHA1/MD5 清单——仅当还要下载校验时才有意义）
- 背景一句话：这批文件应该是什么（来源/用途/大概数量级），用于 sanity check。

## §2 抓取分享页

1. 解析 URL，分离 share id 与 pwd 参数。
2. 优先 `browser_visit` 渲染——迅雷分享页是 JS SPA，裸 HTTP GET 多半只拿到空壳；页面内逐层展开文件夹并记录。
3. 逐项登记：相对路径、文件名、显示大小。**注意页面显示的是 KB/MB/GB 人性化单位**：记录原文 + 换算字节，换算值一律标注为约数。
4. 遇登录墙/验证码/失效页：截图留证，写清阻碍类型，直接转 §6 失败报告。
5. 辅助手段：`web_search` 查该链接或关键文件名是否有公开索引（标 🟡 单一来源），永不把搜索结果当作页面实测。

## §3 清单归一化

统一落成 manifest JSON：

```json
{
  "source": "xunlei-share-page | user-provided",
  "captured_at": "ISO-8601",
  "files": [
    {"path": "目录/文件.ext", "size": 12345, "size_text": "页面原文或null"}
  ]
}
```

路径规范：去前导斜杠、统一 `/` 分隔、Unicode NFC、trim 空白。`size` 未知用 `null`，禁止填 0。

## §4 比对核验

```bash
python3 scripts/manifest_diff.py --expected <基线manifest> --actual <抓取manifest> --out <报告目录>
```

支持输入格式：上述 JSON / CSV（`path,size`）/ 纯文本（每行 `大小<TAB>路径` 或仅路径）。四分类输出：

| 分类 | 含义 |
|---|---|
| missing | 基线有、页面无 |
| extra | 页面有、基线无 |
| size_mismatch | 两边都有但字节数不一致 |
| unverifiable | 页面未显示大小，只能确认存在 |

无比对基线时跳过 diff，直接产清单台账并声明「仅建档，未比对」。

## §5 报告（Markdown 台账固定段落）

链接与抓取时间 → 总文件数/总大小 → 逐项状态表（✅一致 / ❌缺失 / ➕多余 / ⚠️大小不符 / ❓不可核验）→ 可信度标注（🔵 页面实测 / 🟢 多源一致 / 🟡 单一来源 / 🔴 未验证）→ 阻碍与未决项 → 给用户的下一步建议（如「请向发布方索取原始清单」）。

## §6 失败报告格式

一句话结论 + 证据（状态码/页面提示/截图路径）+ 已尝试路径 + 建议用户动作（检查链接有效期、重发提取码、换网络环境）。
