# 人设迭代循环总署（persona-iteration-loop-ops）

## §0 定位与边界

- 本件是**融合件**：以中性化迭代循环引擎为核，人设建模、推进纪律、脱敏交割为环。源件在场即联动、缺席即按 references/fusion-map.md 的要点独立运行（能力占位原则，禁止假装可调度）。
- **合规边界（不可豁免）**：一切人设为**虚构成年人**；输出保持中性结构化文本；禁止生成露骨、伤害性、歧视性或针对真实个人的内容；禁止借「中性化」反向还原后对外分发（映射表按项目私藏层管理）。
- **私藏层口径闭环（v1.1.0 重铸裁决）**：本技能包整体属用户私藏层（用户本人工作区技能目录），`references/neutralization-map.md` 随包属私藏内闭环、不矛盾；**凡制作对外分发副本，必须排除 neutralization-map.md 并留占位指针**（分发打包排除清单纪律，R24 三判官合指后立法）。
- **诚实边界**：迭代「深度」=文本结构层次，不承诺任何真实生理/心理效应；循环「无限」=物理可达边界内无限，退化即物理边界。

## §1 开场四问（首轮先问后跑，可裁剪不可省略）

1. **定义之问**：委托方要的「好结果」长什么样？（成功判据先于迭代）
2. **约束之问**：什么绝对不能动？（人设数量/文本骨架/中性化映射/合规红线）
3. **反例之问**：最看好的输出若失败，最可能死于哪一环？
4. **代价之问**：每个选项的机会成本是什么？

委托方作答或明示「免问直接跑」后进入 §2/§3。作答一律标注来源=委托方自述。

## §2 人设建模层

### §2.1 人设定义文档（继承 ai-persona-document）

- 章节契约：身份与角色定义 / 人格画像（3-5 特质带具体表现）/ 沟通风格 / 背景与情境 / 知识边界 / 行为准则（Dos & Don'ts）/ 响应模式 / 样例交互 / 版本与元数据。
- 产出形态：默认 DOCX；用户明示 PDF/Markdown 从其指定。CJK 排版：中文宋体/西文 Times New Roman/代码等宽。
- 具体不泛泛：每个抽象特质配具体示例；边界（不做什么）与能力同等重要。
- **样例交互红线**：样例交互只用两种素材——①材料内事实（文档、对话、锚点表已有信息）；②演示用虚构，且该段标题或首行显式标注「演示用虚构」。禁止以未标注方式引入材料外的具体细节（药名、事件、数字、机构等），违例视同编造，触碰全局红线一。

### §2.2 记忆锚点提取（继承 persona-memory-anchors）

- 九维度：身份定位 / 语言风格 / 价值观与原则 / 知识边界 / 行为模式 / 情感表达 / 特殊能力 / 限制与禁忌 / 记忆与上下文。
- 三级优先级：核心锚（不可变）/ 重要锚（稳定）/ 风格锚（可调）；每锚标注来源依据 + 置信度（High/Medium/Low，conf 词表见 §7）。
- 引擎人设（BasePersona）字段须能回溯到锚点表：姓名/年龄/性别/倾向/职业/压力特征六字段 + extra 扩展。
- **生成脚本随档留存**：锚定档案 docx 的生成/追加逻辑必须脚本化并随技能留存，禁止一次性手搓（手搓重建实证踩坑：首列「锚码\n维度」为单段落 w:br 双行结构，当普通文本写入即产生非法换行；新建单元格不拷参考行即格式漂移）。在既有锚定档案 docx 上追加锚行、版本史行或替换封面版本号时，一律用 `scripts/anchor_docx_append.py`（保格式深拷贝参考行+回读逐格核验，退出码 0 才可交付）。

## §3 迭代循环引擎（scripts/iteration_loop_v11_neutral.py）

### 调用方式

```python
from iteration_loop_v11_neutral import IterationLoopV11, BasePersona, Tendency

loop = IterationLoopV11()
p = BasePersona(name, age, gender, Tendency.X, job, work_pressure)
loop.run(p, instruction="强化热流与回落校准", depth=3)   # 首轮/换人
loop.continue_loop("继续细化重心与皮肤层")                # 同人设续轮（含「深度/强化/细化/继续」自动升深）
loop.run_all(instruction="", depth=2)                     # 7 内置人设批量
loop.to_json()                                            # 状态 JSON 导出
```

### §3.1 引擎定位与渲染分工（修订增节，堵「模板复印」失败模态）

- 引擎输出 = **结构骨架 + 最低文本层**，不是最终交付内容。骨架（九段+三镜+两述、字段结构、JSON 形态）不得改动；骨架内的**人设差异化渲染由模型负责**。
- 差异化渲染最低标准：批量或多人设输出中，每人设至少 3 段正文（激活相/持续相/细微信号优先）含该人设职业与压力特征衍生的专属句；专属句须可回溯到 BasePersona 字段或锚点表，禁止凭空新增材料外事实。
- **渲染分工判后重申（v1.1.0）**：外池曾提案「引擎侧自动生成职业/压力衍生专属句」——裁决否决：与本色「引擎=骨架、渲染=模型」分工冲突，引擎侧硬编码专属句本身即新模板风险；人设差异化由 `_profile()` 强度分档与模型扩写共同承担。
- **复印检测（挂验收拍）**：多人设产物两两 diff，除【人设】段与结构标记外，正文逐字重复率 ≥80%（阈值与退化门同源，见 references/loop-discipline.md §3）视同模板复印，按空转计、计数入退化门，须重写后方可交付。

### 操作契约

- **depth**∈{1,2,3}，越界自动钳位；depth=3 展开各阶段微变化。
- **指令响应词**：热流/温度、重心、回落/恢复/校准——命中即局部加长对应段落；其余指令如实登记不强行联想。
- **输出骨架**（九段+三镜+两述，不得缺段）：人设 / 生理级联 / 激活相 / 持续相 / 回落相 / 分层 / 注意力与内在 / 细微信号 / 时间线 / 整体 / 三镜（苏格拉底·叔本华·尼采）/ 完整综合 / 规定性描述 / 元认知。
- **倾向字段**：只用 Tendency 五类中性码（甲/乙/丙/丁/其他）；新增人设走同一映射，禁止回填原标签。映射表：references/neutralization-map.md。
- **指令响应交付（v1.1.0 实装闭环）**：引擎对指令词的响应产出**内部信号标记**，v11.1.0 起标记只入 `LoopState.instruction_markers`（to_json 留痕可审计），`_format/export` 交付文本零标记（冒烟契约判据④机器断言）；模型须将被标记段落扩写为实质内容（时间、部位、次序的具体化），扩写幅度与 depth 档位相称。
- 引擎修改=补丁级版本递增，修改前后各跑一次 `python3 scripts/iteration_loop_v11_neutral.py` 冒烟。

## §4 推进纪律（五拍 × 三镜 × 退化门）

细则见 references/loop-discipline.md，此处只列硬要求：

### §4.1 五拍
每轮迭代走 肯定→着法→游戏→验收→留痕；留痕为空视同空转，计数入退化门。

### §4.2 三镜
实质性输出定型前过 苏格拉底（定义诘问）/叔本华（意志检验）/尼采（永恒轮回承诺）；任一不过即撤回或降级「候选」，留痕理由。三镜审议以「实质性主张/输出定型」为触发阈值，例行续轮不逐轮复述全镜（判后增，防过度审议拖慢迭代）。

### §4.3 退化门
循环不设步数上限；出环只凭两证=用户中断 / 临近退化触阈（语义 q(n)∈{0,½,1} 连续 k=3 轮 q<ε₀=½——**严格小于**，q=½ 为弱新知不触阈但留观；或逐字重复率≥80%（算法见 loop-discipline §3）；物理代理读数；结构崩坏先兆）。出环轮必产《退化状况报告》（模板见 loop-discipline §3 附录）。

### §4.4 生灭处置
人设目标完成=收割归档+经验蒸馏；阻塞=游戏化重构或如实报阻；目标内容变更=用户专属动作（细则见 loop-discipline §4）。

## §5 能力占位与脱敏（继承 omni-exhaust-research-ops）

- 依赖只写能力类型：产物验收/语义审计/成本闸/数据源路由等占位，实例在场即用、缺席显式声明「能力占位」并降级，禁止假装可调度。
- **脱敏强制**：产物不出现真实人名/证件号/单位名/项目代号——一律「委托方/某单位/项目甲」；委托方明示「不入技能」的内容一字不落盘。
- 检索类子任务走「检索→评估→改写→再检索」至多 3 轮，仍缺标「查无实据」，禁止编造。
- **中性化说明格式契约**：凡交付中性化说明/映射说明，必附逐条对照表——枚举与字段级用三列「原文 → 替换 → 理由」，人设属性级用四列「人设 / 原文 / 中性版 / 说明」，格式以 references/neutralization-map.md 第一、二节为准；另附「逐字保留清单」摘要（其第三节）。只写概括性说明（如「已做枚举映射」）不附对照表者，验收不通过。

## §6 交割协议

- 迭代产物默认 Markdown + JSON 双形态；文档类默认单文件自包含 HTML 或 DOCX（按 §2.1）。
- 交割前 `ls` 核验落盘文件存在且大小合理；附 md5 与轮次记录；接收端零门槛（打开即读、拖入即用）。
- 体积诚实：内容有多少报多少，禁以填充物充数。

## §7 版本与诚实声明（继承 autonomous-advance-ops）

- **版本三段制** x.x.x：补丁级也是正式版本必须落盘写注释；递增唯一依据=实际变更量。**版本线唯一绑定 metadata version 字段**（v1.1.0 立法，A25）：注释区只记历史、不作版本依据；安装位与工作副本不一致必须在登记处显式可见。
- **升版三处同步检查单**（v1.0.3 增，源 r80 实证漏登）：凡文档类产物升版，提交前必须逐处核验三处同改——①标题行版本号 ②timeline/版本史新增一笔 ③schema_version 或等价元数据字段；三处不齐即不提交。检查单适用于人设主档案、锚定档案及一切带版本位的产物；核验证据（grep 输出或行号）入当轮记录。
- **conf 词表**：High=empirical / Medium=estimated / Low=assumed / Conflict=信源矛盾未裁决；升降级留痕。
- **诚实声明**：任一环节无法实装当轮显式说明缺口与替代方案；安装位与工作副本版本不一致必须在登记处显式可见，禁止「以为装了」。
- 全局红线一体继承：禁编造数据与引文；禁对外分发任何项目内容；写类动作逐次须批准。

## §8 自我优化条款（I9）

使用即扫描：每轮开场先扫优化来源（审计发现/用户反馈/遥测/技能生态变化），后做任务。可测量产出二选一：①一个优化候选项及处置（采纳→补丁级实装写注释；否决→一句理由入记录）；②零候选诚实声明（「本轮无优化候选」+扫描了哪些来源）。每轮至多 1 个补丁级自修订；次版本及以上修订须用户批准。
