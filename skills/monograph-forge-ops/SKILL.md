# 金融分析专著锻造管线（monograph-forge-ops）

> v1.0.0（2026-09-27）：首锻。定位：与 monograph-delivery-ops 互补不重叠——本件管「怎么写」，那件管「交付前怎么验死」。本件从「用户要写」接管，到「稿已成形交棒」为止；渲染、自检、四闸、候批交付一律回 delivery-ops。

## 〇、主流程（七步，序号即依赖，跳步=返工）

1. **开工三问**：①读者拿它干什么（定原型）②这份报告的一句话是什么 ③有没有外部基准。三问答不出=还没有报告，只有素材——停在原地补答，不许带病开工。
2. **🔴 原型门**：输出=选定原型+一句话理由。六原型：学术型/咨询 deck 型/调查型/研报型/论文型/科普型。**选错原型是最贵的错误**：把要被引用的做成 deck 没人能引，把开会用的做成 60 页学术报告没人会读。爸爸专著默认科普型骨架+研报型多页免责声明组件（与 delivery 步骤 1 同源，此处为写作侧首次定型）。
3. **数据承重层立法**：建 `数据表.json`，每个数字五字段（§2）；**verified 权责开工时立法**——仅亲自读到一手来源的核验责任人有权置 true，调研席永不置位。权责不立，「交付前清零未核」的闸永远清不了。
4. **写正文**：四角色（研究员/编辑/信息设计师/数据可视化师）依次成为，五条硬规矩（§3）。机制与文献定位（§4）不许省——省了就是资料汇编。
5. **口径停点**：每章写完过停点清单（§5）；长书跨会话续写走停点卡恢复。
6. **🔴 交棒门**：稿成形定义=交棒清单全绿（§6）。交棒三件套：正文稿+数据表.json+停点记录，移交 delivery-ops。
7. **写作期自检**：`python3 scripts/draft_lint.py <稿目录>` 过机械闸（§9）；人眼层只留机器判不了的（章首场景、比喻承重、basis 是不是一句完整话的最终判）。

**顺序铁律：数据表必须先于正文。** 先写正文再补数据，一定会出现「这句很顺，但我不确定那个数字的口径」——到那一步再回头查，通常的结果是把这句留着不查。

## 一、开工三问（①定生死）

| 读者要 | 原型 | 特征 |
|---|---|---|
| 引用你的数字 | 学术型 | 竖版、方法论透明、Figure 编号、预先反驳自己 |
| 拿去开会说服人 | 咨询 deck 型 | 横版 16:9、一页一结论、标题即结论句 |
| 理解一个群体 | 调查型 | 竖版双栏、问卷原题随图、大数字视觉锚 |
| 查具体数据 | 研报型 | 竖版、Exhibit 编号、表格密度高、中性描述标题 |
| 同行评审 | 论文型 | 英文、LaTeX、IMRaD、contributions 显式列出 |
| 无背景读者理解并行动 | 科普型 | 三幕骨架、场景开篇、口径搬侧栏、结尾工具箱 |

- **一句话写不出=没有报告**：写不出一句读者会复述给别人的话，就只有素材。
- **没有外部基准=半成品**：只有内部对比（这条比那条好）的报告，读者读完仍不知道该不该行动。能查就查（数据插件席），查不到在方法论里明说缺了它。
- 论文型换生产轨道（LaTeX），渠道有一票否决选题的硬约束——动笔前必读上游 `references/论文.md`；科普型与学术型的差别不在严谨度在叙述骨架，动笔前必读上游 `references/科普.md`。

## 二、数据承重层立法（数据表.json）

每个数字五字段，缺一不可：

```json
{"id": "E1", "value": "19%",
 "basis": "22–25 岁在 AI 高暴露职业的就业水平，低于「若与低暴露同龄人同速增长」的反事实水平",
 "n": "ADP 行政工资单，覆盖数百万美国工人，截至 2026-06",
 "src": "Stanford Digital Economy Lab, Canaries in the Coal Mine?",
 "date": "2026-08-12", "verified": true}
```

- **basis 是承重字段**：写不出一句完整的口径话，这个数字就不能用。口径不清或拿不到 N 的数据点，一律不进正文。
- **verified 权责开工立法**：开工时白纸黑字定「谁在什么条件下有权置 true」（本项目约定：亲自读到一手来源）。调研 agent 只填 value/basis/n/src，永不置 verified——349 条挂红「未核」的事故（上游实证）就死在这一步没立法。
- **金融数据源登记**：src 字段对插件取数写成「插件名/接口/参数/日期」（如 `iFinD/财务指标/600519,2025年报/2026-09-27`）。插件返回的数字**未经一手来源核验不得置 verified=true**——接口返回 ≠ 一手核验。
- **cite 两种句子**：正文用 cite("E1") 标记的句子=数字来自被引来源；不带标记的=作者判断。这个区分做出来，读者能自己决定信到哪一层；不做的综述，读者只能整体信或整体不信。
- 口径写在用得到它的那一页（正文括号、图注 N、科普型侧栏），不搬附录；完整数据表随交付物给文件。**附录是参考文献表不是数据表转印，体量闸：附录≤正文 10%**（实测反例：370 页的书附录占 35%，逐条印 349 个数据点口径，没有任何读者那样读）。

## 三、正文写作：四角色与五条硬规矩

**依次成为四个角色，跳过任何一个产出缺一整层**：
1. **研究员**三件事：定口径、给机制、定位文献——只做第一件交出去的是资料汇编；最常被跳过的是后两件。
2. **编辑**决定读者读到第 3 页应已知道什么；砍掉一切「因为查到了所以写进去」和「我们是怎么做的」自我叙事。
3. **信息设计师**建立让 60 页保持一致的系统（标题层级、图表编号、数据源行格式）。
4. **数据可视化师**判据不是「哪种好看」，是「读者要拿它比什么」。

**五条硬规矩**：
1. **每个数字都要有分母**。「多数企业正在部署」是废话；「951 家里 7%（Bain, 2026）」是数据。
2. **图表标题写结论不写主题**（唯一例外研报型：查数的读者要中性描述）。
3. **预先反驳自己**：列替代解释→说明怎么排除的→**诚实说出没排除掉的**→主动降级结论。第 3、4 步是多数人不敢写的，恰恰是让报告成为引用锚点的东西。
4. **附录是参考文献表**：一条来源一行，长度跟来源数走，不跟数据点数走。
5. **不写「我是怎么做的」**：判据=删掉这句读者对结论的判断变不变？不变就删。样本框、纳入排除、口径统一规则是方法论必须写；工具实现与中间故障是工程记录，不写。

**行文句式**（详见上游 `references/行文.md`）：
- 摘要用编号事实法（每条可单独引用），必须能独立读懂；方法有变化时方法在前发现在后。
- 先给数字再给解释，不要反过来；「我们发现」跟数据，「我们认为」跟判断，混写则整段可信度按最弱句算。
- 变化量和水平量分开说（「42%（2017 年是 29%）」）；具体到荒谬的细节就是可信度。
- 措辞禁忌：没有分母的百分比、把趋势说成因果、用新数据踩旧数据、形容词代替数据、单一来源当共识。
- 数据源行区分「谁采的数」和「谁做的图」；调研数据 n 是这张图的 n 不是全报告的 n。

## 四、机制与文献定位（汇编→研究的分水岭）

- **机制**：给可检验的**竞争假说**而非单一说法，并说清现有证据能否区分。**给机制不等于下结论**——诚实地说「现有证据分不清这两种解释」比硬选一个更有价值。
- **文献定位**三问：这批数据印证了什么既有判断？修正了什么？揭示了什么既有框架没建模的维度？——第三行含金量最高，是同行判断作者懂不懂行的第一个信号。
- **分析层次标清**：任务/岗位/组织/宏观四档；跨源对比前先问「这两个数字在同一层次上吗」。层次错配是伪矛盾的第一来源（任务级增强恰恰是岗位级替代的前提）。
- 摘要回答「发现了什么」，结论回答「合起来意味着什么」；结论章只是摘要重述=第二三层没做。

## 五、口径停点与续写推进（金融特化）

**写到哪停，开工立法**：
1. **描述与机制到此为止，操作建议永不出现**：不写目标价、买卖评级、收益承诺；「该不该买」类问句一律拒绝并回免责锚。
2. **前瞻内容用条件句**：情景表述（「若 A 则 B」），不给单点预测；预测区间的口径（谁测的、什么模型、什么假设）进 basis。
3. **免责锚一次置位**：frontmatter+文头注释锚定，正文不反复声明；必要声明一句带过放末页。
4. **时效停点**：金融数据有时效——正文每个时效敏感数字带 date 字段口径；续写时超 30 天的市场数据回数据插件席重取，不沿用旧稿。

**续写停点卡（跨会话恢复件）**：每章写完落 `停点卡.json`：{已成章清单、各章停点句、数据表版本哈希、口径冻结清单、下章计划}。续写从停点卡恢复，不凭对话记忆续——记忆跨会话会漂，停点卡不会。
- 每章独立落盘（文件+版本号），聊天内版本空转=事故（零落盘是最严重失败模式）。
- 多 agent 分章写作时：**能写成函数的规则不许留在手册**（加粗预算、章长方差、标点后空格归 longdoc_check 报数；markdown 方言与生成器开工对齐一次，生成器对不认识的块抛异常——静默透传最坏）。

## 六、交棒门（稿成形定义，全绿才移交 delivery-ops）

- [ ] 原型组件清单齐（按 §1 表格逐件核对：摘要/目录两级/局限性单独成节/结论超出摘要）
- [ ] 数据表.json 五字段全、basis 抽查能读成完整话、verified 权责记录附卷
- [ ] 机制分析≥1 处且为竞争假说形式、文献定位三问有答
- [ ] draft_lint.py 全绿（§9）
- [ ] 时效停点核过：市场类数字 date 在 30 天内
- [ ] 停点卡.json 落盘（长书）
- 交棒三件套：正文稿 + 数据表.json + 停点记录。从此渲染、自检、四闸、候批归 monograph-delivery-ops，本件不再经手。

## 七、失败模式（如果→则）

1. 如果一句话写不出→则停在第 1 步补答三问，不许带素材硬开工；否则返工率最高的就是原型选错。
2. 如果 basis 写不出完整口径话→则该数字不进正文，记 needs_review；不许先写上「约」「近」蒙混。
3. 如果 verified 闸清不了→则回查开工时权责立法是否缺席；缺席则补立法并逐条回溯，不许批量置 true 冲闸。
4. 如果续写发现口径漂移（同一指标前后章定义不同）→则以停点卡口径冻结清单为正本统一回改，登记漂移事件；不许各章自洽了事。
5. 如果发现自己把趋势写成因果→则降级为「与……同时发生」并补替代解释段；除非做了因果识别。
6. 如果章数/页数不够→则能加的只有真正缺失的横截面分析与关键数字速查表；凑字数的过渡段读者一眼看穿，加附录不算加内容。
7. 如果 draft_lint 报「%无 N」密集命中→则逐条回数据表补 n 字段或删句；不许调宽阈值换全绿。
8. 如果用户要买卖建议→则拒绝并回免责锚，把内容改写成情景条件句；红线无例外。

## 八、反模式黑名单

| # | 反模式 | 替代做法 |
|---|---|---|
| 1 | 先写正文再补数据 | 数据表先于正文，顺序铁律 |
| 2 | 只整理不给机制与文献定位 | 研究员三件事做全，竞争假说+文献三问 |
| 3 | 没有分母的百分比、形容词代替数据 | 每个 % 带 N；删形容词上数字 |
| 4 | 工作日志/使用说明/免责清单进正文 | 判据：删掉读者判断变不变；声明一句带过放末页 |
| 5 | 「本报告」高频自指 | 主语换成现象与数据；自指密度是外行程度指标 |
| 6 | 插件返回数字直接置 verified=true | 权责立法：仅亲自读到一手来源者置位 |
| 7 | 数据表逐条印进附录凑体量 | 附录=文献表，体量闸≤正文 10% |
| 8 | 凭对话记忆续写长书 | 停点卡.json 恢复，口径冻结清单为正本 |
| 9 | 把「会写」当「写得对」 | 判据只有 lint 输出与交棒清单 |
| 10 | 单点预测/目标价/买卖评级 | 情景条件句；操作建议=红线，回免责锚 |

## 九、自检

```bash
python3 scripts/draft_lint.py <稿目录>           # 机械闸全项
python3 scripts/draft_lint.py --smoke            # 自检（含负断言）
```

机械闸五项：①数据表五字段与 basis 启发式（长度/谓词）②正文 %无N 扫描 ③「本报告」自指密度 ④工作日志句式扫描（踩坑/一开始/下载环节类）⑤附录体量闸（附录/正文≤10%）。机器判不了的（章首场景、比喻承重、basis 最终判、原型选型）只进人眼清单，不硬编函数冒充已检。

## 十、诚实边界

- 蒸馏自 MIT 许可开源仓 alchaincyf/huashu-report（写作侧：SKILL.md、结构骨架/行文/研究深度/生产流水线/科普/论文/实证基线七件 references）；仓方自报统计（41 份解剖、篇幅基线等）按**待验证假设**引用，本件不背书。

- 本件不构成投资建议（免责锚置顶）；交付物默认内部学习使用，禁外发，外发须经机主逐次批准。
