# WPS、Supabase 与 ima 接入使用记录

本轮取得三个平台的实际读取结果。WPS 通过已安装的官方 CLI 提供 stdio MCP；Supabase 使用官方托管 MCP 与 OAuth；ima 使用官方技能 1.1.10，并由自主实现的只读 stdio 适配器提供五项查询工具。各平台的配置、授权、正文读取、云端写入分别留痕。

WPS 云入口文件是指针，不能当作正文。云端文件 ID 已由独立基本信息请求核验；本轮遇到名称由“A2A”调整为“Agent to Agent”的情况，旧入口与新入口字节一致，保留旧快照并另记名称变化。正文导出成功，其他四份文档及文档库读取返回 403。对不可读取、缓存候选和原生格式候选均明确记录其验证边界。

ima 官方接口的实际知识库字段为 kb_id/kb_name；只按文档示例中的 id/name 解析，会产生“请求成功但名称为空”的假象。适配器兼容实际字段，取回两知识库及项目资料。下载原件时，访问信息只留在内存中，完整 DOCX 经 DPAPI 加密保存，派生正文遮蔽已知凭据形态。云原件与本地当前版本存在差异，不能互相替代。

Supabase 读取确认两个项目均健康，public 表结构分别有 19 与 17 张表。现有协作通道、广播、语义锚点与租约表可作为后续接入的基础。普通 SELECT 验证事务只读；发现的 RLS 缺口作为单独的修复事项登记，不能在“已接入”的表述中隐去。

Neon 的只读参数是 readonly=true，Supabase 使用 read_only=true。二者均采用供应商官方 OAuth；用户无需在聊天中发送 API Key。Neon 本轮等待授权回调超时，仍只记录为已配置。

代码外发仅包含自主实现与本规范；ima 官方原包安装在本机，未将其捆绑进公开仓库。重试产生新回执，保留旧失败证据。协作报告发布与其他席位签收分别记账，避免把目录复制或共享库活跃时间当作网络握手。

R7 历史检查曾检测到已有 A2A 服务在线，读取 Agent Card 与健康状态后，使用既有技术席位发送汇总通告。本地节点的响应通过 HMAC 校验且请求 ID 一致；向五个合作席位路由的请求返回未签名的入队应答。R8 的新卡片、健康和自身请求均被拒绝连接；R9 再次读取卡片及健康路径仍为 ConnectionRefusedError。这一变化推翻当前可用性结论。历史成功、路由入队、数据库 active 标签均不证明本轮节点或其他席位在线。服务未启动或重启；自身信箱与签收仍需可用服务及既有正常 MFA 路径。

已配置当前对话的定期核查，每 5 分钟执行有界检查，状态未变时保持安静，出现有意义变化或需用户处理的新事项时通知。此为定期检查机制，不是连续流式监控。华为云 X 使用效能已列入汇报验收，当前未取得实际云端作业回执，耗时、CPU 利用率、吞吐量与费用均未实测。

R8 接续读取观察到 WPS 基本信息版本 61、ima 项目计数 3,991；R9 分别变为 64 和 3,992。R9 指定文件独立身份和标题仍与原绑定一致，WPS 新正文含 878 个文本块、22,971 个字符，完整原始导出 JSON 已在受控目录加密捕获并验证解密字节一致。元数据和导出未固定为同一事务快照，不能称为版本 64 的原生完整快照或云历史备份。其他四件 WPS 指针正文、此前 403、原生格式、云 ACL 与完整历史仍分别待核。

本轮按 ima、Supabase、Neon、WPS、百度顺序检查，未完成授权的 Neon 和百度跳过实际读取，也未重启 OAuth。两个 Supabase 项目仍健康，普通 SELECT 的 transaction_read_only=on，第一项目文件分块表 RLS 关闭且策略数为 0，第二项目没有该表；本连接保持只读。十件本地源资料和两个目录均重新读取与批注，主 DOCX 再次变化，完整加密捕获及同快照预检通过；与 R8 比较只有一段正文变化。WPS 新导出也仅一个文本块变化。程序全文重读、结构差异比较与受控改变段落审议分别留痕，没有把指针字节或自动比较称为全文人工审议。

只读发现器已实现并取得回环实测，十项边界检查通过；标准方法调用和他席签收仍待取得。新的产学研协同与迁移追溯要求单独记录，主控台及 SOC 连接未核验，不以本地文件副本宣称已经同步。

SDD 013 补充了夜间排期组件，48 项本地检查覆盖午夜、07:30 收尾、08:00 结束、供应商账户时窗、规则失效、任务与云样本绑定以及非法输入。自填 verified 只属于外部规划声明，纯计算组件不负责签名验真或任务执行。暂行价格规则快照早于观察下界或到期时返回 needs_revalidation；不同实例、范围、负载或单位的样本不得比较吞吐。真实华为云 X 执行、费用、独立席位确认仍需实际回执。

KooCLI 7.2.12 已核验，本次正常 profile 查询结构缺少官方示例中的 profiles/current 字段，因此配置数量未知；不能将缺字段解释成没有配置。尚未取得云认证、目标实例和执行通道。Kimi 正常 browser API 当前没有可操作浏览器表面，官方入口打开返回 queued，故未取得账号与产品端技能加载证据。
