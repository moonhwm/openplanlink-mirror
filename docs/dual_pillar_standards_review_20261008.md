**二、密码分类与 PQC 纠错**

| 名称 | 官方可证内容 | 声明应修正为 |
| --- | --- | --- |
| HMAC-SHA3-512 | HMAC 是使用共享秘密密钥的消息认证码；SHA3-512 是 SHA-3 家族的杂凑函数。[NIST HMAC 规范草案](https://csrc.nist.gov/pubs/sp/800/224/ipd)、[FIPS 202](https://csrc.nist.gov/pubs/fips/202/final)。SP 800-224 当前所访问页明确标为 Initial Public Draft，不能写成最终发布标准。 | 可以描述消息完整性与共享密钥认证；不能直接称为公钥数字签名或证明公开签名者的不可否认性。512 位输出也不能单独证明系统具有 512 位安全强度。 |
| AES-256-GCM | AES-256 是 256 位密钥的对称分组密码；GCM 是附带关联数据的认证加密模式。[FIPS 197](https://csrc.nist.gov/pubs/fips/197/final)、[SP 800-38D](https://csrc.nist.gov/pubs/sp/800/38/d/final)。 | 描述对称认证加密；系统实现仍需给出密钥、IV/nonce、标签、错误处理等证据。算法名称不能证明公钥身份认证或完整 PQC 部署。 |
| SM9 / IBC | 国家密码管理局公告发布了 GM/T 0044-2016 SM9 标识密码算法；国家标准项目说明其签名采用椭圆曲线双线性对、用户私钥由密钥生成中心生成。[发布公告](https://oscca.gov.cn/sca/xxgk/2016-03/28/content_1002407.shtml)、[国家标准项目说明](https://std.samr.gov.cn/gb/search/gbDetailed?id=5DDA8B9DC27D18DEE05397BE0A0A95A7)。项目说明用于核验技术结构，不冒充标准全文。 | IBC（Identity-Based Cryptography）是标识密码体系的类别，不是单独的后量子算法名。SM9 标准身份不能自动产生 PQC 身份；密钥生成中心的信任和主密钥管理还需单独审阅。 |

**三、AGPL 与 SSPL 的组合**

[MongoDB 官方 SSPL 正文](https://www.mongodb.com/legal/licensing/server-side-public-license)第13条，在向第三方提供该程序功能作为服务的适用条件下，要求提供 Service Source Code；范围包括用于提供服务的相关管理、接口、自动化、监控、备份和托管代码。[MongoDB 官方 FAQ](https://www.mongodb.com/licensing/server-side-public-license/faq)说明 AGPL 与 SSPL 第13条的不同、SSPL 没有获得 OSI 批准，并明确普通 SaaS 使用 MongoDB 数据库并不当然等同于提供 MongoDB 服务。

因此，`AGPL + SSPL` 只能作为待澄清的许可证描述，不能直接断言兼容：须区分同一衍生组合、独立程序聚合、通过接口通信，以及由完整权利人提供二选一的双授权。已直接获取 [GNU AGPLv3 官方正文](https://www.gnu.org/licenses/agpl-3.0.txt)（HTTP 200），核对第10条禁止附加限制及第13条修改版本的网络交互源码义务。第13条对 GPLv3 的特定组合许可不能外推成对 SSPL 的通用许可。另已实际访问 [MongoDB 发布的 AGPL/SSPL 官方比较 PDF](https://assets.contentstack.io/v3/assets/blt7151619cb9560896/blt8838baa131549873/69c192eb2c3765374ee5ebbc/SSPL-compared-to-AGPL.pdf)。项目结论应写为“许可证组合与分发/服务方式待逐项审阅”，待补组件清单、版本、版权归属、实际许可文本及组合方式。
